# E3f-4b：点击后核对并播放

更新：2026-11-09。

## 目标与原因

主人反馈进食按钮始终不可用。现场为 E3f-4a / E1.18；设备重启后目录为 `idle`，尚未重读。USB 显示查询约需 3.4 秒，回复有效期为 2 秒，下一次查询又会暂时占用发送通道，界面反复清空状态。

本步完成电脑端准备流程，让主人点一次即可核对、播放。设备使用当前 E3f-4a，进食与日常交互继续按实际观察验收。

## 实现

- E3f-4b 会话就绪后，自动只读当前目录一次，并显示读取进度；失败时保留手动重读入口。重连或重启使用新会话，重新读取。旧版工作台保留手动读取。
- 将 USB 连接、查询进度和上次查询结果分别显示。过期数据标为“上次查询”，仅用于界面展示。
- 同会话已读到能力和完整目录后开放播放入口。点击后最多核对 12 秒，每 150 ms 查看本机状态；显示查询刚更新、`can_submit` 为真且状态年龄加 HTTP 往返小于 350 ms 时，仅发送一次原表情命令。
- 核对期间遇到设备、启动或会话变化、对话、其他页面、播放器未就绪时结束本次操作。停止查询与重复点击沿用现有规则；断线和超时给出明确结果。

接口仍为 `GET /api/studio/state`、`POST /api/studio/command`，使用现有 `read_catalog`、`neutral`、`embarrassed`、`eat`。数据流：明确点击 → 本机核对 → 唯一 USB 所有者 → 原调度 → 原播放器 → 设备回执。所有设备期限和串口节奏沿用当前实现。

依赖为工作台实时控件、现有目录控件、主机控制桥和现有请求协议。离线单元测试覆盖准备期限、身份变化、最新状态和一次发送；HTTP 与浏览器测试模拟慢查询、目录重读、断线、忙碌和重复点击。实机先验证目录和稳定入口，再由主人观察进食画面及菜单。

## 交付顺序

本阶段执行顺序：修复与测试 → 独立复核 → 更新本机服务 → 核对连接和目录 → 主人点击验收。后续按[当前主线](project-mainline.md)完成逐素材布局，再沿用验收版适配资源安装与角色节点。
