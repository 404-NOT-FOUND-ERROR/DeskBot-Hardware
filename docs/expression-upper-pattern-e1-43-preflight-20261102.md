## 为什么还需要这一轮

全为 `FF` 的样本即使 read/mmap 一致，也可能掩盖错误地址返回同样擦除数据的情况。需要让上半区具有确定的非 `FF` 内容，并在设备 CPU 上证明读到正确位置，之后才能迁移活动表情包。

## 首个最小实验

候选范围为 `0x01000000..0x01010000`，恰好一个 64 KiB mmap 页、16 个 4 KiB 擦除扇区；当前正式表没有在这里分配分区。该选择必须由写前实际分区表重新确认，不能只依赖历史报告。旧资源 `0x5EC000..0xBC8000`、独立模型和旧表继续保留。

准备一个带固定版本、逐块偏移标记和 SHA-256 的确定性 64 KiB 图样；保存完整母文件。图样必须区别于擦除态及对应低地址内容，且各 4 KiB 块互不相同，以检测地址别名和错误偏移。这个图样只是地址测试数据，不是 EAF、资源包或新分区。

## 分开执行的门禁

| 门禁 | 必备证据 | 失败处理 |
| --- | --- | --- |
| 离线准备 | 图样/清单摘要、扇区对齐、容量/重叠检查、越界和错设备负向测试 | 不生成可执行写入清单 |
| 写前 | COM4 身份、当前 App/bootloader/分区表/资源摘要；完整 32 MiB 现场备份及独立校验；目标页精确回退 | 不写设备 |
| 单页写入 | 明确范围的部署清单；esptool 校验；上半区目标页完整回读；低地址保护区对照 | 恢复精确原始页并回读 |
| CPU 验证 | `esp_flash_read` 与 mmap 对照整页摘要；逐块偏移核验；跨 `0x00FFFFF0` 的边界样本；映射释放/空闲页和堆快照 | 不迁移资源，保存原始错误 |
| 回退与回归 | 恢复原目标页、原 App；分别回读；正常启动；菜单/对话/摸头/睡眠唤醒人工回归 | 保留精确恢复路径，不叠加新功能 |

专用 CPU 探针必须单独审阅与构建，只在诊断任务中访问上述固定只读范围，不接受任意地址参数，不增加网络接口，也不接入 UI/LVGL 回调。当前 E1.42.3 校验器固定期待 `FF`，不能通过改写其历史预期冒充新图样验收；下一轮需要新的 schema、校验器、负向用例和参考摘要。

## 随后的顺序

1. 已知图样跨界验证通过后，测试 8 MiB 连续 mmap 的可用页、释放和运行内存；小页通过不等于整区通过。
2. 再准备保留旧资源/model 的 `upper-assets-8m` 部署与精确回退；先将已验收 E1.18 包原样迁移，不同时新增表情。完整包校验、模型加载、LCD 与交互回归独立验收。
3. 扩容通过后才导入一个新表情，复核圆屏布局、镜像/非对称、循环和语义绑定。设备活动包先采用 7 MiB 软上限，余下 1 MiB 作为资源余量。
4. 后续角色映射、只读客户端出口、资源更新仲裁和 DeepSeek/TTS 分轮接入；底座修复后的外壳识别可靠性另行恢复。

32 MiB Flash 空间、16 MiB PSRAM 与 MMU 连续页是三种独立预算。上半区图样通过也不代表 EAF 解码、动画显示、原子更新或角色切换已经实现。
