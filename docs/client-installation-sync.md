# 安装结果同步到客户端

目标：主人确认安装、设备显示并保存后，客户端接收同一安装记录，知道当前使用的外壳与表现配置。持续个体、记忆、关系和成长阶段沿用原记录。

本轮交付是安装事实同步：包含持久接收、当前形态查询、重试与重开恢复。A/B 当前的人格为空、音色未配置；这两项保留客户端现有设置。配置怎样参与聊天与实际发声，在下一轮接入原对话及语音入口。

## 数据流与接口

`安装服务当前记录 → 核对设备首帧与保存 → 本机 HTTP → 客户端原 SQLite → 当前形态查询`。

| 接口 | 输入与结果 |
| --- | --- |
| `POST /api/hardware/installations` | `schema / source_id / source_revision / installation / device`；返回接收凭证、是否重复及当前安装编号 |
| `GET /api/hardware/installation?character_id=…&device_id=…` | 最近已同步安装、外壳、完整表现配置、接收时间与凭证；标明设备信息是同步时的快照 |
| 同步命令 | 指定工作台、客户端、来源编号、持续个体及设备；仅发送当前已保存记录，输出客户端接收结果 |

来源编号固定于一份安装记录库，修订取原安装状态的 `revision`。`installation` 保留安装编号、个体、设备、外壳、方案引用、确认时间、配置与关联摘要以及完成依据；`device` 为本次查询的设备实际结果。

接收器使用客户端原持久层、设备登记及持续个体核对函数。以新增 HTTP 路由组合原服务，原接口继续使用原处理器；实例启动时显式指定允许的来源。请求使用本机地址、JSON 和 `X-DeskBot-Integration: shell-installation-v1`。

## 采用与恢复规则

- 只同步当前安装；等待、失败、需重新确认或已被替代的记录保留原进度。
- 核对安装与当前设备的角色、图摘要、首帧、保存及身份。完成依据可以是关联回执，也可以是安装服务重开后重新查询的设备结果；两类依据分别保留。
- 客户端设备登记必须属于同一个体。完整配置与关联摘要按原规范校验。
- 安装编号与冻结的安装记录用于去重；相同编号的内容变化返回冲突。当前查询的设备序号、会话和查询时间独立保存。相同安装的新查询可返回原凭证。
- 同设备固定一个来源，按来源修订排序；同源同修订对应不同安装时返回冲突。旧确认晚到时保留新安装；重复旧请求即使携带更高状态修订，也只返回历史凭证与当前编号。迁移时再显式变更来源。
- 安装记录和当前形态在同一个 SQLite 事务中保存。回应丢失沿用原编号重试，客户端重开读取原凭证。来源修订重置时先迁移来源记录。
- 同步只记录安装事实；人格、音色和成长阶段分别显示接入状态。空人格与未配置音色保留客户端现有值。旧壳重用建立新的安装记录，生活状态持续保留。

## 依赖与验证

沿用 `ShellInstallation`、客户端 `createSqlitePersistence` 与设备登记；Python 与 Node 使用已核对的明确路径及标准库。原 USB 所有者、App、资源和客户端运行存档继续作为当前基线。

单元覆盖摘要、身份、完整回执、来源修订、去重、事务失败与重开。旧版迁移资料、磁场来源和主人确认按原规范校验；文本按 Unicode 字符计数，空白人格与空音色标识保留现有设置。手动安装的执行目标保持 `source:null`，关联中单独保存磁场来源。

集成使用原 Node HTTP／SQLite、实际安装服务及生产 ControlLink 内存设备，验证 A→B→A、等待后同步、回应丢失、重开及迁移资料的跨语言往返，并比较原生活与成长记录。同步命令核对当前目标筛选和接收凭证。

源码、接口往返及测试结果独立归档，由另一 AI 复核。本轮完成后接角色配置与音色的实际采用，再串联角色内容和制作项目。
