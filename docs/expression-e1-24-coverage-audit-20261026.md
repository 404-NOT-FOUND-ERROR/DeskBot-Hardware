# E1.24 表情绑定静态覆盖审计

E1.24 汇总 E1.4a 语义清单、E1.14 保护决策、E1.19 部署映射快照、E1.22 视觉选择和 E1.23 写入预检，生成[机器可读审计报告](../artifacts/expression-e1-24-coverage-audit-20261026/report.json)。审计只读取已归档文件，使用 SHA-256 锚定输入；不连设备、不访问串口、不构建固件或写入数据。

## 结果

- 静态行为路由 56 条：20 条行为路由、29 条语义路由、7 个未映射名称；未映射调用共 9 个调用点、7 个不同名称。
- 29 个语义入口中，23 个仅由审计范围内的动态 API 进入，5 个有本地字面量入口，1 个为状态入口。动态入口只表示源码允许传入该值，不证明实际收到或播放。
- 当前 E1.18 记录的映射覆盖 29 个语义及 18 个官方 EAF，18 个资源均至少被一条语义引用。共享资源按 E1.14 保护分类保留。
- 用户选择保留 `surprised → shocked.eaf`；`Happy.eaf` 候选未选择，映射未变。此视觉决定不是部署授权。
- 设备运行时轨迹没有采集；29 个语义和 56 条路由都没有本轮设备观测证据。因此不据本报告删除、合并或替换资源。

审计不能回答各语义在真实对话中的触发频率、LCD 实际呈现、播放器并发行为或动作是否完成。下一阶段应先制定有界、被动的运行时观测设计：明确事件来源与脱敏字段、重复合并/采样规则、缓冲上限、导出/清除流程、UI/音频线程隔离及关闭时零行为影响。完成设计评审后，才决定是否需要单独的固件采集实现和实机验证。
