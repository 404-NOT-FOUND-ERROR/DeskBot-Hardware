# 摸头接入生活存档

2026-11-19。目标：桌宠回应摸头，同时让同一个体留下这次真实互动。

链路：头部三连触 → 原 USB 所有者 → 本机转发 → 客户端身体感知 → 生活存档。

设备沿用已验收的 E3f-9d.4b-touch 和小智回应。工作台识别本版 `Touch: Triple PRESS_DOWN detected!` 日志，在原观察事件中增加 `head_touch`，值为 `triple:<设备运行毫秒>`。事件绑定当前设备、启动编号和观察段。

本机接收接口为 `POST /api/hardware/head-touch`，字段：

- `device_id / boot_id / firmware_sha256`：已登记本体与当前固件。
- `uptime_ms / observed_at`：设备运行时间与首次观察时间。

转发每秒读取 8780 的原观察结果，按设备、启动编号和运行时间生成稳定事件编号，重试沿用原时间与内容。待发记录保存到独立 SQLite；超过 5 分钟记为过期。客户端用同一编号防重，输入和世界变化在原事务内保存。

接收端绑定 `shaping-001` 与已验收本体，复用本机凭证和正式存档的唯一写入服务。调用现有 `sensor.touch` 身体入口，保留来源、身体注意与经历；小智负责当次回应。

依赖：原串口观察器、Python 3.13、Node 24、客户端 input-store／persistent-world／body-perception。复用 4311 服务与 8780 串口，保持原生活开发与语音分享入口。

验证覆盖：日志分片、设备与启动切换、重复、过期、服务重试、事务失败和存档重开。集成使用独立数据库和实际 HTTP；正式运行检查连接、登记和待发状态，实机摸头后核对保存回执。

进度：摸头闭环与本机后台恢复已完成；接续身体输入联网 → 最小日常版 → 客户端生活与愿望联调 → 制作和安装体验。

本轮结果：81 项自动测试通过。正式服务已启用，4 次设备三连触分别对应 4 条输入、身体感知和记忆，待发为 0；重复提交已有事件返回原回执，存档版本保持不变。主人确认反复试触、回应与菜单正常。此次接入依赖电脑上的 8780、转发服务和 4311。

现场材料在 `tmp/body-touch-client-20261119/`，含启用前状态、真实记录、重复回执和启动入口。暂停同步可在该目录创建 `stop` 文件；接收服务可按原存档与凭证启动 `client-original` 模式。已保存互动继续保留。[本机后台恢复](body-touch-resident.md)已通过 27 项测试、服务重开与观察接口重连验证，原 4 条互动保持；物理 USB 拔插接续日常联测。
