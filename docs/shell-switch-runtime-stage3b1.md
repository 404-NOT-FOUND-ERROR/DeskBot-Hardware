# 阶段 3b1：实时数据接入与原日志联测

目标：把现有 USB 所有者收到的磁场回调接到识别器，再交给阶段 3a 换角适配器。本轮用保存的原日志与内存设备验证，现场采样按既有记录接续。

## 实现路径

`USB 原接收器 → 有界磁场事件 → 原 M2 识别器 → 已确认外壳与角色 → 换角请求 → 首帧 → 保存`。

1. `MagneticStream` 解析已有 `cmd=06` 回调，保存最近 64 条有效事件；事件包含连接、设备、启动、会话、递增序号、接收毫秒与原负载。作为现有传输的可选字段，旧工作台仍可读取。
2. `ShellSwitchRuntime.update(control, stream, now_ms)` 消费当前会话的新事件。档案按传感器与安装基准恢复；重复事件忽略，丢包、断线、改版与转动重置识别窗口。识别观察交给原适配器，`next_command(now_ms)` 交给既有连接所有者执行。
3. 原日志联测按保存窗口逐段重放，保留段内采样间隔，段间明确重置观察；内存连接使用真实主机协议。正式关联继续要求已验证档案、对应设备和当前角色版本。历史或待复核来源显示识别结果与待办。

运行时间使用单调毫秒，支持持续运行超过一小时。识别与交互按同一时钟核对；首帧和保存分别记录。当前磁场回调没有动作状态，转动由调用者显式提供；现场接入时补核动作来源。

样本时效沿用原接收时刻，发送前再次核对，取 M2 与换角层时限的较小值。转动结束、档案替换与记录边界后的新样本重新积累；已交接请求继续收尾。

## 接口与依赖

现有工作台 `/api/shell-characters/replay-session` 接收 `expected_revision / session_id`，返回逐窗口识别、模拟切换与回执记录，随配置版本保存。页面沿用“我的外壳”下的原日志入口。

依赖既有 `SessionStore` 日志与档案、M2 识别器、阶段 3a、`ControlLink`。USB 保持唯一所有者；本轮不启动自动实机执行服务。模拟设备身份沿用被重放项目，结果标明原日志与内存设备。

联测总预算为 6,000 个调度点，生成时间线前检查；页面等待最长 60 秒，超时后可重新读取保存结果。每个窗口保留最后输入识别与尾部过期结果，分别显示。

## 验证与后续

单元覆盖负载解析、边界大小、身份、重复与丢包、过期、重连、转动及长时间运行。集成覆盖原日志经过真实识别器、请求、首帧与保存；HTTP 和浏览器覆盖结果重开、版本更新及错误恢复。由另一 AI 复核，原配置与采样文件核对摘要。

2026-11-16 结果：281 项单元与集成测试、135 项浏览器检查通过，独立 AI 复核通过。现有 3 个项目、10 个窗口、1,831 条原采样重放完成；来源保持历史或待复核状态。49 份原配置与采样文件摘要一致。结果见[本轮归档](../artifacts/shell-switch-runtime-stage3b1-20261116/report.public.json)。

下一步：3b2 实时调度与启停状态可先离线实现；3b3 接续正式采样、确认角色关联并验收 A/B 自动换角；随后开发人格与声音。
