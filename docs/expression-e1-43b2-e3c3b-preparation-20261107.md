# E3c-3b 映射测试准备

更新：2026-11-08 · 状态：工具、现场备份、恢复计划与独立审计通过

## 目标

为已验收的 E3c-3b 保存当轮备份和 App 恢复计划，接续三分钟映射交互测试。本轮沿用已构建的探针，不修改固件。

## 接口与数据流

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `load_e3c3b_build_reference()` | 固定构建报告、人工验收与镜像 | 当前 App、ELF 标识和分区布局 |
| `validate_e3c3b_snapshot()` | 32 MiB 快照、设备身份 | App 与迁移静态区检查、当轮 NVS 摘要 |
| `prepare_live()` | 新运行标签、已审计探针报告 | 现场快照、原 App 擦除范围、候选、计划与启动记录 |
| `audit_preparation()` | 上述材料 | 独立重算的准备结果与计划编号 |

```mermaid
flowchart LR
    A[已验收 E3c-3b 与探针报告] --> B[核对 COM4 身份]
    B --> C[读取当轮 32 MiB 快照]
    C --> D[核对 App、资源和静态区]
    D --> E[启动原 App]
    E --> F[保存恢复计划]
    F --> G[独立审计]
    G --> H[下一步映射期间交互]
```

## 实现与依赖

- 新增 E3c-3b 基线模块、准备入口与审计入口，历史 E3c-3a 入口保留原样。复用现有只读 COM4 传输、App 事务和日志检查。
- 固定已验收 App 摘要 `180aa8cb…d0f42a`；探针为 `66b887e2…fa76b2`，原有 4,092 B 显示分块及发送错误处理随基线保留。
- 当前 App 为 4,489,232 B，探针为 4,494,096 B；计划覆盖两者的扇区并集 `[0x10000,0x45a000)`，恢复字节全部来自当轮快照。
- NVS 范围为 `[0x9000,0xD000)`，记录当轮摘要；bootloader、分区表、资源、模型和其余静态区与迁移记录逐段核对。
- 固定 IDF Python 3.11。数据只写入仓库 `tmp/` 与 `artifacts/` 的新目录，日志与文件摘要关联。
- 准备成功须同时完成完整快照核对、恢复计划保存、原 E3c-3b 启动 ELF 和日志核对。读取或验证失败时保存已有记录并尝试启动原 App，启动结果单列；该轮保留为失败。执行探针的入口在准备审计通过后接续。
- 本入口每块读取一次，与独立审计逐块对应；读包截断时保留分块和日志，结束当轮读取并启动原 App。

## 测试与完成条件

单元测试覆盖当前/旧 App、错身份、静态区变化、NVS 更新、截断快照、候选或报告变化、路径跳转、输出冲突和禁止写入。集成测试使用真实计划核心与模拟 COM4，核对整片快照、恢复范围、启动记录、读块日志关联，以及删除候选后仍能加载恢复材料。

离线测试与另一名 AI 复核通过后，执行 COM4 只读备份，并独立审计。人工操作在 `hold[0]` 至释放前的约 180 秒内完成，逐项记录起止时间与结果；测试菜单往返、对话中/后切菜单、摸头、睡眠唤醒后，同轮恢复 E3c-3b。恢复后验收单独记录，新表情验收接在该测试之后。

## 菜单问题的通用检查

1. 区分画面、页面逻辑、触摸和音频，先保留卡住时的日志。
2. 核对显示所有者、刷新等待、发送错误和完成通知；成功、失败和重试都要结束本次刷新。
3. 同时评估内部静态数据、运行堆、最大连续 DMA 块、任务栈和单笔传输大小。总空闲内存不能代替连续块大小。
4. 新候选沿用当前显示补丁；每次都覆盖联网前后、对话中/后、菜单往返、触摸与睡眠唤醒。主机测试和实机结果分别记录。
