# Grok 圆形 EAF 素材库

日期：2026-11-11。目标：为两套角色提供明显不同的表情风格。

## 结论

已将固定圆形轮廓的 23 种表情转换为 EAF，并生成可播放、筛选和下载的本地素材库（本机留存：`artifacts/grok-round-eaf-20261111/index.html`）。完整脸居中，关闭镜像；下一步用于两套角色的手动切换。

按用户确认的个人非商业实践用途保存本地素材，随库保留上游 LICENSE、RIGHTS 和 THIRD_PARTY_NOTICES，记录源码提交与文件摘要。

## 核对结果

| 项目 | 源码与文档结果 | 对 DeskBot 的意义 |
| --- | --- | --- |
| 素材形式 | 网页实时生成 SVG；C++ 实时生成 Gray8 像素 | 不是现成 EAF 文件，需要导出帧再编码 |
| 动画内容 | 35 个状态、25 种轮廓，包括待机、倾听、开心、难过、害羞、困惑 | 可研究同一角色如何在不同语义下保持风格 |
| 运动方法 | 弹簧缓动、眨眼、视线、变形和粒子 | 可作为原创角色动效的设计参考 |
| 色彩 | 网页有彩色粒子；C++ 输出灰度 | 保留彩色需要从网页渲染帧；灰度转换不能恢复原色 |
| ESP32 适配 | 已从标准 C++ 核心导出帧并编码为 EAF | 设备接入沿用现有资源管线，完整脸需要登记布局 |
| 许可 | 自定义个人非商业研究许可；第三方动画、形象与来源代码另有权利 | 新增代码与来源动画分别核对授权 |

## 接入路径

```mermaid
flowchart LR
    A[有授权或原创的动画] --> B[电脑导出帧与播放参数]
    B --> C[EAF 编码与压缩]
    C --> D[登记布局和角色语义映射]
    D --> E[工作台预览与安装]
    E --> F[手动切换角色并实机验收]
```

- 先选待机、开心、难过、害羞、困惑、困倦六类，服务角色对比。相同语义连接各角色自己的素材；统一角色轮廓，保持辨识度。
- 完整脸设置居中、镜像关闭；单眼素材使用镜像布局。新完整脸需要扩展当前按 `eat.eaf` 摘要登记的设备路由。
- 现有 `protocol/eaf_encode.py` 接受 RGBA 帧，`protocol/eaf_preprocess.py` 提供重编码与帧存储去重。程序动画导出后成为固定片段，实时视线和随机动作需要另行设计。
- 每段登记尺寸、帧率、循环及切换规则。检查循环衔接、圆屏裁切、布局切换、菜单与对话；按成品包核算容量和解码开销。
- 活动资源区 8 MiB，发布软预算 7 MiB；E1.45 内容为 5,981,260 B。电脑保存完整母库，设备安装选定素材。

## 转换设计

- 输入：固定提交的 C++ 渲染核心，形状固定 `blob`；仅导出保持圆形脸的 23 个状态，沿用原名。12 个会变为圆点、雷达或图标的特殊状态排除。
- 数据流：60 Hz 动作推进 → 20 fps Gray8 与透明度 → 圆屏蒙版与 15 级灰度 → 4-bit EAF 编码、压缩与官方末帧标记 → 回读解码 → 动态预览和清单。黑眼睛保留不透明，背景透明；灰度误差按 RGB565 显示结果核对。
- 输出：360×360、单次 8 秒；完整脸居中、镜像关闭。片段保留原时序，循环衔接在绑定角色时另选；两套角色的素材都保存在电脑母库。
- 依赖：已有 Zig C++ 编译器、固定上游源码、现有 EAF 编解码模块、带 Pillow/NumPy 的 Python 环境。仅构建桌面导出器。
- 验证：固定圆形、帧数与时间、EAF 完整性、全帧像素回读、圆屏裁切、重复导出的确定性和容量；结果与源码摘要一同归档。临时帧按状态处理后释放。

接口：`scripts/grok-round-render.cc` 导出 `GKR2` 流（尺寸、帧率、帧数及逐帧灰度/透明度平面）；`protocol/grok_round_assets.py` 编码 EAF；`scripts/build-grok-round-eaf.py` 生成文件、解码预览、清单与检查报告。

## 表情衔接

需求补充：同一角色连续切换表情时，位置、眼形、缩放和运动节奏应自然接续；持续动画的尾帧也要接得回首帧。

上游 `Motion::setState()` 在同一实例里保留全局时间和位置等弹簧，`expression()` 从当前眼形重新插值。现有导出器为每种状态单独 `reset()`，因此 23 段是独立素材片段，尚未包含跨片段衔接与可循环区间。源码另有 `setSmoothPresentation(true)`，用于连续调整眼睛尺寸和间距。眨眼、旋转和粒子仍由各状态控制，接点需逐项观察。

实现分两步：

1. 先做电脑对照：同一圆形引擎依次运行“待机 → 开心 → 难过 → 待机”，与现有独立片段直接拼接对比。连续序列另存为一个 EAF，预览从 EAF 解码，记录切换帧与像素变化。它用于验证连续引擎效果。
2. 再制作可组合角色包：每种表情定义“进入、持续、退出”，共享中性衔接姿态；发布时检查各接点和循环。先做常用六种。头部位置、方向、尺寸、眼形及粒子收尾共同纳入接点要求。

工作台显示这些片段和接线，支持连续试播。调度器按片段完成回调切换、合并快速重复请求；菜单与睡眠按原交互及时响应。共享衔接姿态减少资源数量；全部接点按解码帧核对，并在设备上检查空帧、闪屏和切换延迟。仅有淡入淡出不能代替眼形和运动的连续变化。

对照接口：独立桌面导出器接收固定状态时间线，沿用 `GKR2` 与现有 4-bit 编码；输出单个序列 EAF、直接拼接对照、预览页和检查报告。单元测试覆盖时间线边界与非法输入，集成测试覆盖状态切换时不重置引擎、全帧解码、圆形与无镜像。设备播放与角色调度在角色包阶段接入。

已完成同步对照（本机留存：`artifacts/grok-round-transitions-20261111/index.html`）：160 帧连续样片约 533 KiB，全帧 EAF 回读、7 项单元与原生测试、浏览器同步播放和逐帧检查通过。重复同状态分段与整段输出一致；原始大帧已清理。报告记录三处接点及其前后多帧变化，样片播放到末帧停止。

常用六种已完成[可组合角色包与节点试播](grok-role-clips-20261111.md)：18 段去重后 1,244,597 B（1.19 MiB），426 帧精确回读、循环与 30 对接点通过。进入、持续、退出共用中性姿态；连续点选采用最新目标。23 段原素材继续保存在母库。

下一步：登记完整脸布局，接入手动双角色切换、选择保存与发布；完成实际包容量和设备播放检查。随后接外壳自动切换、角色对话，常用表情组合按需要补直达过渡。
