# 阶段 3a：自动换角适配与会话联测

目标：把“磁档案识别 → 已确认外壳 → 完整角色 → 设备表达切换 → 首帧 → 保存”接到现有单 USB 会话。先在电脑内存设备上联测，下一步接实时采样与实机。

## 接口与数据流

`ShellSwitchAdapter` 接收关联快照、带设备和档案摘要的识别事实，以及现有 `studio_control_link` 状态。`observe(fact, at_ms)` 输入识别；`update(control, at_ms)` 输入设备状态；`next_command(at_ms)` 产生最多一条现有格式的命令；`retry(at_ms)` 显式接续失败；`snapshot()` 返回目标、已显示、已保存及原因。I/O 由原连接所有者执行。

`fact` 包含 `identity`（连接、设备、启动、会话编号）、递增 `sequence`、`archive_sha256` 与 `observation`（状态、磁档案编号）。时间由调用者提供，当前联测会话范围为递增的 0–3,600,000 ms。正式关联由 `project_bindings()` 生成；内存联测单独生成模拟来源。

关联使用完整角色编号与修订，操作使用 `expression_role_id`。正式识别要求来源版本一致且完成离线验证；场景联测使用单独标注的模拟来源。目录的设备、启动、会话、角色图摘要与索引逐项核对。主页、待机、稳定安装且播放器可用时提交；说话、转动、菜单和内容更新时保留最新目标。

主机 `ControlLink` 新增可选 `role_attempt`：主机命令编号、操作、实际会话请求编号。创建于真正发送请求时，重连清除，后续查询继续保留。适配层据此匹配 `activation.request_id`；排队回执、首帧已处理、选择已保存分别记录。角色目录和首帧只证明表达，语音状态保持待接入。

识别事实带当前连接身份与递增采样序号，只消费新观察。断线、设备或启动变化后重新读状态并等待新识别。适配器交出命令时即记录在途，原单 USB 所有者随后发送；交接前可替换目标，交接后先核对该次结果再收敛到最新目标。旧连接、旧请求和过期观察保留为丢弃记录。

直接拒绝按回复外层请求编号关联，后续状态查询按内层执行编号关联。关联改版后仍记录旧请求的设备事实，完整角色确认采用新版本。超时先重读状态，保存失败保留“已显示、待保存”，显式重试后接续。相同角色的不同外壳复用已生效选择。

依赖：阶段 2 协调器和关联库、M2 识别结果、`ControlLink`、`RoleQueryClient`。内存联测走真实主机编解码与单条在途调度，模拟设备生成协议回复；HTTP 只运行内存联测，不调用工作台的真实连接对象。

## 页面与验证

现有“我的外壳”增加“会话联测”，沿用 A/B 与场景选择，展示识别、角色解析、请求、首帧和保存，并标明模拟设备。结果随配置版本保存。

单元：身份与来源、版本变更、菜单/对话延后、旧回执、首帧与保存、失败和重试。集成：真实 `ControlLink` 完成会话、查询与换角，覆盖保存失败、断开重连和丢回复。浏览器：关联后的联测、结果重开、错误恢复与窄屏；核对真实设备命令为零。

`POST /api/shell-characters/session-lab` 接收 `expected_revision / scenario / shell_a / shell_b`，沿用同源 JSON、8 KiB 上限与现有提交头。结果带配置摘要，保存到外壳库的 `last_run`；重开可读，配置变化后提示重跑。
