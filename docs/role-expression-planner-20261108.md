# 角色到表情的电脑联调

目标：工作台选择一个角色和表情后，直接看清当前连接、目标资源，以及接下来应“发布资源”还是“发送表情”。沿用现有角色草稿、节点预览和设备会话。

`resolve(draft, semantic, source, context, request_id)` 返回 `ready / planned / needs_publish / unavailable / busy / stale`。电脑先核对草稿版本、资源指纹、布局与播放参数，再核对设备会话和当前请求能力。结果给出原因和下一步；发送仍走现有单个 `neutral` 命令与回执。

数据流：角色草稿 → 语义接线 → 当前资源目录 → 表情接口能力 → 发送命令 → 原应用调度。真实目录绑定当前设备、启动号、连接号和会话；重连后重新分析。保存的 E1.18 目录用于离线对照，结果显示“电脑预演”。

E3d-2b 的目录、重连、联网重启和日常交互已验收；真实目录与 E1.18 快照的 36 项一致。`neutral` 的受理与提交播放器回执通过，对应 `winking.eaf` 眨眼动画。接下来完成资源专项，再做害羞资源替换和角色接线。角色名字沿用 `role-default` 请求契约；角色激活、更多表达、外壳与角色绑定、DeepSeek 和声音分步接入。

HTTP 拒绝无效来源、格式或超大草稿时，先发送明确状态，再在 1 秒、512 KiB + 1 B 范围内读取剩余请求内容。这样 Windows 客户端能收到完整结果；内容进入解析前仍按原大小与来源规则核对。

接口：本机 `POST /api/role-expression/resolve` 读取当前桥接状态；输入可选择 `saved_snapshot` 或 `device`。该接口只分析，不触发设备命令。页面显示角色 → 语义 → 资源 → 圆屏的链路，并能跳到现有节点编辑器。请求 ID 生成固定命令 ID，重复提交由现有命令去重处理；发送时再次核对实时会话。

验证：草稿/目录版本变化、缺少绑定或资源、同名文件不同摘要、帧率/镜像/附带动作、忙碌、状态过期、重连、重复命令；实际解析器接生产 HTTP，电脑设备模型验证请求和回执，浏览器验证桌面/窄屏/减少动画设置。
