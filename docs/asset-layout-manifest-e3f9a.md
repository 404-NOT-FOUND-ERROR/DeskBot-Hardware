# E3f-9a：镜像选择在设备生效

更新：2026-11-12。实现、双配置构建和离线审查完成，设备仍为 E3f-7 / E1.45。

目标：工作台资源上的“镜像”选择用于圆屏播放，设备目录返回同一布局。当前基线为 E3f-7 App / E1.45 资源。

## 接口与数据流

工作台草稿 → `deskbot-layout.json` → 资源装载时校验并登记 → 原表情播放器 → 圆屏；真实目录读取同一登记结果。沿用 `Configure / Reset / FullFrame / Play / OnFrame` 接口和原 USB 查询。

清单版本为 `deskbot.asset_layouts/v1`，包含角色编号，以及资源名、SHA-256、宽高、布局、镜像值和设置来源。`eye_anim` 为左侧定位并生成镜像，`full_frame` 为居中显示一次，`listen_anim` 沿用系统聆听布局。完整脸与单眼都可以手动改变选择。

依赖：现有 Emote/GFX、cJSON、mbedTLS、PSRAM 和 E3f-7 冻结构建。新增配置默认关闭；关闭版与 E3f-7 比较，开启版单独检查体积、内存和函数栈。

## 实现规则

- 只在资源装载时解析、检查摘要和尺寸；最多 64 个资源、32 KiB 清单、4 层 JSON。登记表放在 PSRAM，播放和逐帧回调只查表。
- 清单按资源登记，同一资源的多个语义共用设置。只有全部条目通过才应用；缺少清单或清单无效时采用既有布局，并记录结果。
- 布局 v1 对应当前 360×360 圆屏：双眼布局为左中对齐、偏移 10/10；完整画面居中。系统聆听独立处理。资源摘要、全部图像帧尺寸、布局与布尔值必须相符。
- 重载和回退释放旧登记；保留首帧重排、失败恢复、4092 字节显示传输和现有 USB 节奏。

## 验证与交付

单元测试覆盖清单格式、重复项、摘要、尺寸、数量、分配失败与重载。集成测试使用真实 EAF：生成包 → 装载 → 镜像/居中交替播放 → 真实目录；覆盖语义共享、首帧、播放失败及恢复。构建完成后由另一个 AI 复核。

实机依次观察完整画面、双眼和手动调整，再测菜单、对话、摸头与睡眠唤醒。安装前保存同轮恢复材料；测试不设操作时间窗口。

本轮交付固件、默认布局包、单眼居中对照包，以及基于现有 E3f-7 安装记录的离线 App 计划。计划保存原 App 擦除范围的全部内容；正式安装时重新读取设备状态和 NVS，再形成当轮恢复材料。资源包单独安装、单独恢复。

测试结果：95 项 Python/原生、44 项 Node、42 项浏览器检查通过，并以 42 组像素条件对照实际 GFX。默认和单眼居中资源包各 5,986,416 B，均保留 E1.45 全部原成员；7 MiB 建议线余 1,353,616 B。App 开关双配置构建通过；开启版 4,524,592 B、余量 1,619,408 B，内部静态数据增加 16 B。离线安装计划以 E3f-7 / E1.45 为恢复点。
