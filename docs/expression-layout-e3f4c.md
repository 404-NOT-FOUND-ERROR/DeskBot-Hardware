更新：2026-11-10。

## 目标与现状

主人已验收 E3f-4c。此前按钮等待出现在点过“播放平静”之后，保留为切换路径回归；进食与平静现已使用各自布局。

已核对 `eat.eaf` 为 360×360、75 帧、20 fps 的完整画面；原 E3f-4a 将普通表情统一送到 `eye_anim`，布局为自动镜像、偏移 10/10。`winking.eaf` 为 125×160 的单眼素材，两者使用不同布局。

## 设计

素材 → 语义接线 → 布局配置 → 设备目录与能力 → 原播放器 → 屏幕观察。

- 素材记录文件摘要、尺寸和明确的显示方式：`full_frame`（完整画面）或 `mirrored_eye`（单眼镜像）；显示方式由素材设计决定，尺寸只用于边界检查。
- 完整画面采用居中、偏移 0/0、镜像关闭；单眼保持现有偏移和自动镜像。进食与平静互相切换时，一起恢复各自的布局。
- `inspect_layout(asset, expression, layout, requirement)` 返回当前方式、目标方式、差异与接入条件。输入按资源摘要对应；旧目录继续描述设备实际布局。
- 预览和发布审阅使用同一份配置。节点显示“素材 → 布局 → 圆屏”；替换时核对文件、帧率、循环、镜像和裁切。
- 当前官方加载器只读取表情的文件、帧率和循环，布局属于共用对象。独立布局需要接入原显示所有者，并使实时目录报告实际路由；单改资源包中的新字段无法改变设备显示。

依赖：当前 E1.18 资源快照、EAF 解码与圆屏合成器、已核验目录、节点预览、原 Emote/GFX 所有者。第一步完成布局契约、真实资源对照和播放切换回归；随后实现设备路由、目录与发布联动，再构建和实测。

## 设备版接口与执行

`deskbot_asset_layout::Configure(handle)` 在资源加载成功后读取原眼睛布局，并按文件、字节数和 SHA-256 登记已审核的完整画面。`Play(handle, emotion)` 在原递归图形锁内查找实际素材、设置镜像与对齐，再调用原 Emote 播放入口。布局设置或原入口返回错误时恢复前一布局；资源卸载前清空登记。其他素材继续使用资源包原眼睛布局。

`FullFrame(data, size)` 向目录构建器提供已启用的素材路由；目录同时核对真实摘要，并增加居中且无镜像的 `full_frame` 布局。目录摘要随路由变化，电脑协议兼容旧目录。当前发布器继续按原资源格式生成，布局登记在 App 中管理。

验证包括真实 C++ 播放切换与失败恢复、真实资源目录和协议对照、关闭/开启两版构建。关闭版对照 E3f-4a；开启版仅部署 COM4 App，以同轮完整备份恢复 E3f-4a。实机观察进食、平静切换和日常菜单操作，结果单独记录。

原生测试执行生产布局与目录代码，使用真实 E1.18 资源、cJSON 和 SHA-256；GFX/Emote 替身核对锁、调用顺序、首帧坐标与返回错误。官方播放器的解码和圆屏最终画面由固件构建及实机观察验证。

首帧使用原 `update_cb`：按有边界的 EAF 帧表定位首张图像，跳过 `_C` 元数据回调。尺寸就绪后，在同一图形锁内重排并完整刷新一次；其他对象和后续帧沿用原绘制。测试分别模拟“先绘制、后首帧”和“首帧直接到达”。
