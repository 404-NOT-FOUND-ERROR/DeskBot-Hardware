## 当前 E3c-3b 接续设计

入口 `scripts/run-expression-continuous-mmap-e3c3b.py`，依赖[当轮准备与审计](expression-e1-43b2-e3c3b-preparation-20261107.md)、既有 COM4 App 传输与事务核心。仅适配当前基线，不修改固件或历史入口。

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `check` | E3c-3b 运行标签、准备审计 | 离线重算审计、核对计划，返回准备状态 |
| `execute` | 上述输入与计划编号 | 核对身份、原 App 启动与当下快照，运行探针，同轮恢复 E3c-3b，保存结果 |
| `recover` | 运行标签、原 App、计划与恢复日志 | 续做恢复；结果另行编号，恢复不依赖候选和构建报告 |

数据流：当轮审计 → 身份与 Flash 核对 → 保存恢复意图 → 临时探针 → 保持映射 → 恢复原 App → 回读与启动核对。App 擦除并集为 `[0x10000,0x45a000)`；其余静态区核对摘要，NVS 分别记录测试前后摘要。原版启动还核对 E3c-3b ELF。

测试覆盖离线检查、审计变化、计划编号、设备变化、读取中断、恢复续做，以及真实事务核心的成功和故障路径。人工交互按 `hold[0]` 到释放前的实际时间记录，恢复后验收另存。当前先完成工具与备份，交互窗口在实测时启动。

本轮 11 项专项测试和独立复核通过；COM4 备份、准备审计及离线 `check` 通过。执行前读取失败时，原 App 启动清理结果单独保存；恢复入口用固定摘要核对 E3c-3b 原字节和擦除并集。详见[现场准备结果](../artifacts/expression-continuous-mmap-e1-43b2-e3c3b-20261107/live-preparation-result.json)。

## 需求分析

本记录描述已完成的 E3c-3a 临时连续映射探针及当轮原 App 恢复。当前设备已更新为验收通过的 E3c-3b；下一轮先按[适配设计](expression-e1-43b2-current-baseline-design-20261107.md)重新构建探针与恢复计划，再测试映射期间交互。

## 方案设计

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `check` | 运行标签、v5 准备审计 | 重新计算审计、核对候选与回退计划；离线准备结果 |
| `execute` | 上述输入、精确计划 ID | 重新读取整片 Flash，核对当前 App 与计划保护区，记录当前 NVS 摘要，执行探针并自动恢复；结果、串口日志、回读与恢复记录 |
| `recover` | 运行标签、计划、原 App、恢复日志 | 继续未完成恢复；按编号新增结果 |

入口为 `scripts/run-expression-continuous-mmap-e3c3a.py`。依赖现有 App 事务核心、固定 COM4 传输层和 E3c-3a 准备审计器；沿用已构建的固件，代码增量只在电脑端。`recover` 只读取原 App、计划和恢复日志，候选、构建报告及全片快照可离线移走。

```mermaid
flowchart LR
    A[v5 准备审计] --> B[现场身份与整片 Flash 核对]
    B --> C[保存恢复意图]
    C --> D[临时探针 App]
    D --> E[三分钟连续映射与交互]
    E --> F[恢复原 App]
    D --> F
    F --> G[回读、启动、人工验收]
```

执行入口先核对当前设备身份，再启动原 App 并重新读取 32 MiB Flash。事务核心逐项检查 App 回退字节和计划保护区；保护区变化时不创建写入意图。NVS 不参与写入，执行时记录最新摘要，并在恢复后对比变化。首次写入前，完整恢复字节和恢复意图已落盘。写入接口只接受计划中 App 起点、长度和字节。出现日志错误、中断或测试失败，事务核心恢复原 App；恢复过程再次中断时由 `recover` 续做。所有输出使用独占文件，保留原准备证据；后续读取日志和结果另行编号。恢复只依赖计划、原 App 字节和事务日志，不依赖候选镜像。

## 测试验证

单元测试覆盖计划确认、审计篡改、错设备、当前 App/静态区变化、错误写入范围、候选删除后的恢复和证据冲突。事务核心测试使用模拟设备运行成功与故障路径；执行入口集成测试调用真实事务核心与真实恢复日志，但以模拟设备替代串口，检查恢复后整片 Flash、App 和日志状态。

实机顺序：写前核对 → 诊断 App 回读 → 8 块内容校验、19 次采样、至少 180 秒保持 → 自动恢复 → App 回读与静态区核对 → 启动 → 人工菜单、对话、摸头、睡眠唤醒。联网交互和屏幕效果由用户反馈逐项记录。

设备保持映射 180 秒；电脑采集窗口为 450 秒，覆盖启动等待、区块校验和保持过程。Flash 写前、恢复后各读取 32 MiB；当前每 MiB 约 30 秒，沿用同一进程执行。

本轮自动探针通过：8 个区块摘要一致，19 次采样，保持 180,047 ms，释放后 189 页全部恢复。解析器 21 项检查通过；内部空闲堆最低 43,271 B、最大空闲块最低 23,552 B，任务栈余量 3,284 B。采样期间为配网状态，音频空闲；人工交互和联网对话另行验收。
