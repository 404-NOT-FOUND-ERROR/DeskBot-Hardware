# E3f-1：安装与回退入口

更新：2026-11-09 · 安装与回退工具完成，56 项离线测试通过；实机按主人方便时安排。

目标：把已有安装演练接成现场工具，完成“安装 E1.45 → 重读目录 → 安装害羞 App → 观察圆屏”的链路。平静动画的观察和设备安装安排在主人方便时进行。

## 设计

| 命令 | 输入 | 结果 |
| --- | --- | --- |
| `prepare-offline` | 已保存参考与候选 | 用于模拟的 App 计划 |
| `prepare-live` | 当轮已安装 E1.45 的资源事务 | 重新读取 32 MiB，保存当前 App、NVS 和现场计划，保持下载模式以便接续安装 |
| `check` | 已保存计划 | 校验版本、资源、来源和 App 擦除范围 |
| `install` | 现场计划编号 | 仅写 App，回读并检查启动；失败时恢复同轮原 App |
| `recover` | 同轮备份与事务日志 | 恢复 E3d-2b，保留 E1.45 和当前 NVS |
| `resume-original` | 尚未写入或已恢复的现场计划 | 启动原 App；以后安装时重新准备快照 |

数据流：E1.45 安装日志 → 新鲜设备快照 → App 计划与回退备份 → 原有 App 事务 → 完整范围核对与启动记录。

计划保存在仓库 `tmp/e3f1-app-日期-名称/`。App 擦除范围为 `0x10000–0x460000`。恢复只读取同轮材料，独立于候选包、构建目录和资源安装源目录。整体恢复顺序为 App → 资源。

现场准备与安装连续执行，期间保留下载模式，使 NVS 与写前备份一致；准备失败时启动原 App。每次安装、恢复或返回原版本分别编号记录，前置检查和传输初始化失败也保留本次结果。

依赖：已有 `studio_e3f1_deployment` 核验、`studio_app_deployment` 事务、固定 E3f-1 构建及既有 COM4 传输。现场传输按需加载；离线准备和检查不加载串口模块。固件、显示驱动和 USB 接收节奏沿用现有版本。

## 验证

- 单元：版本、身份、范围、资源安装状态、计划模式、来源和路径。
- 集成：真实命令入口与生产传输配合内存 Flash，覆盖准备、安装、回读、启动、失败恢复和重复恢复。
- 关键边界：旧资源或离线资源计划不能生成现场 App 计划；写入前核对全片；恢复保留运行时 NVS；测试临时备份自动清理。

离线验证入口为 `scripts/validate-studio-shy-installer.py`：18 项安装器专项、19 项安装顺序测试、19 项原 App 事务回归。报告绑定源码、留存输入与日志摘要；加 `--check` 重核已保存结果。测试使用内存 Flash 和模拟命令执行器。

56 项全部通过，失败、错误、跳过均为 0，19 份源码、3 份留存输入和测试日志摘要已核对。见[测试报告](../artifacts/studio-shy-e3f1/installer-validation.json)。当前设备继续使用 E3d-2b / E1.18，平静画面待主人观察。

## 使用顺序

先用 Offline 环境运行验证器；现场命令使用 Build 预检确认的 IDF Python，入口为 `scripts/deploy-studio-shy-e3f1.py`。

1. 确认平静画面后，使用资源事务安装 E1.45，重读设备目录。
2. 执行 `prepare-live --run <新名称> --resource-run <本轮资源事务>`，再 `check --run <同名>`。
3. 接续 `install --run <同名> --confirm-plan <计划编号>`，完成 App 回读、静态区及启动检查。
4. 若本轮先结束，执行 `resume-original --run <同名> --confirm-plan <计划编号>` 启动原 App；再次安装时新建计划。
5. 回退使用 `recover --run <同名> --confirm-plan <计划编号>`；恢复原 App，并保留 E1.45 和当前设备设置。

实机时由主人确认平静画面；安装 E1.45 后重读目录，再安装 E3f-1，验证害羞动画和菜单、对话、摸头、睡眠唤醒。角色表达映射接在这一轮之后。
