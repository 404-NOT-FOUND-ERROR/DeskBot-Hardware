# E3f-9c：设备角色图与连续播放

日期：2026-11-12。目标：设备读取 E3f-9b 的同一份角色包，执行单段或“进入 → 持续 → 退出”动画。本轮范围是离线实现、测试、构建和复核，实机接续主人方便时进行。

## 接口与数据流

`deskbot-roles.json` + 布局清单 + EAF → 装载校验 → PSRAM 角色表 → 语义请求 → 片段播放器 → 完成回调 → 下一片段。

- `Configure(handle, schedule, initial_blocked) / Reset` 与资源装载、卸载配对；装载方从既有同步快照传入页面与应用的暂停原因，新角色表发布前完成初始化。状态未知或切换中先暂停；每秒按确定状态同步菜单和聆听位，保留独立睡眠位。读取快照释放临界区后再进入 Emote。校验图版本、字段、资源摘要、帧数、布局引用和默认角色。图最多 32 KiB、8 层、4 个角色，每角色固定六项日常语义，单片段最多 512 条记录。全部通过后启用。
- `Request(handle, semantic)` 使用当前角色；`Select(handle, role_id)` 为后续手动启用预留内存接口。保存选择、USB 角色命令和工作台启用接续 9d。
- `Snapshot.selected` 是最新选择目标；退出段仍可能属于旧角色。9d 分别回报选择目标、实际播放角色与阶段，并区分接受和完成切换。
- `SetBlocked(handle, reason, value)` 分别处理菜单、聆听和睡眠三类位；临时动画按实际覆盖层可见性处理。多个原因独立累积。恢复时保留当前片段位置与最新目标。
- `OnFrame` 接收原 GFX 回调，只处理眼睛对象。片段完成后向现有应用队列提交一次后续播放；队列任务核对代次，重载后的旧任务直接结束。

## 播放规则

单段按草稿循环或停在末帧。三段按实际播完回调推进；新请求只保留最后目标，当前进入或持续段播完后退出，再进入新目标。退出段完整播放。角色切换沿用相同接口，原有身体动作仍只由语义请求触发一次。

菜单切换通过应用队列暂停、回主页后恢复；UI 及其外层手势回调不获取 Emote 锁。聆听暂停角色播放；目标板的睡眠回调尚未接入，本轮只保留通用入口。系统聆听动画、通知和临时动画沿用原入口。临时动画结束由既有每秒状态更新检查。恢复继续当前片段，下一次完成时处理最新目标。原角色图未覆盖的语义沿用旧表情，并结束当前角色片段占用。

镜像与首帧几何继续使用 E3f-9a 登记结果。EAF 的最后终止记录不作为图像播放；调度计数采用物理记录，图中的 `frames` 采用图像帧数。逐帧阶段只更新少量计数，解析和摘要校验放在资源装载时。

卸载前先停止并隐藏眼对象，再释放角色表与资源映射；排队任务通过代次识别旧资源。

## 依赖与验证

依赖现有 Emote/GFX、布局与首帧重排、cJSON、mbedTLS、PSRAM 和应用主队列；保持菜单 DMA 修复与 USB 节奏。新增开关默认关闭，分别构建关闭版和开启版，并检查 App 余量、静态内存、函数栈和原分区输出。

单元测试覆盖图格式与容量、资源和布局不一致、帧数、分配失败、阶段顺序、快速改目标、单段循环/末帧、叠加暂停、恢复和旧回调。集成测试使用真实双角色包与实际 C++ 播放入口；核对原资源兼容、镜像和首帧路径。另一 AI 复核设计与代码。

实机后续观察两角色的六项表情、连续切换、菜单往返、对话、摸头和睡眠唤醒；同时验证包回退。下一步 9d：工作台手动启用角色并保存选择，再接换壳自动启用与人格、声音和动作。

## 复现入口

从实际 Git 根运行，使用[架构](architecture.md)登记的解释器。Offline Python 执行 `-m unittest tests.test_studio_role_player_e3f9c -v`。24 项测试运行生产角色图、布局和播放器，并编译冻结 GFX 的原始计时回调，覆盖两角色、末帧、连续切换、暂停续播、旧队列失效与分配失败。

IDF Python 执行 `scripts/build-studio-role-player-e3f9c.py --resume`，生成独立的关闭/开启构建；`--check` 只读核对。入口从 9a 冻结源码叠加本轮十个文件，复跑仅更新这批文件，原日志按编号保存。报告位于 `artifacts/studio-role-player-e3f9c/`，构建和日志位于同名 `tmp/` 目录。
