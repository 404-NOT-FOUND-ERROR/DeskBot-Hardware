回读后已用已验证的 USB reset 流程恢复正常 App，并采集 45 秒启动日志。日志观察到 `app_main`、LCD、触摸初始化、16 MiB PSRAM 和 MXIC OPI_STR 启动，没有 panic/assert/abort。该次启动未联网，未重新做屏幕交互回归；用户此前已接受的恢复基线回归是独立记录，不扩展到这次快照后的睡眠、DOA、底座或表达资源验收。启动时发现缺少 `icon_speaker` 与 `icon_tips` 的既有警告，本阶段未改动相关资源。

- `tests/test_upper_backup_gate.py`：8/8 通过，覆盖设备/安全状态拒绝、App 擦除并集、扇区边界、精确回退字节与文件摘要。
- 既有图样/运行结果专项 34/34、分块捕获/独立校验专项 8/8 通过；合计 50 项与本轮门禁相关的测试通过。
- `scripts/audit-expression-e1-43a3-backup.py --check`：通过；重新核验 32 个分块、独立原样校验、1,061 个固件源文件哈希、18 个归档构建文件及三段回退。
- 全可移植套件运行 449 项：444 通过、2 跳过、1 失败、2 错误。未通过的三项均为此前已记录的 E1.26 历史冻结检查，分别拒绝后续 Kconfig 扩展、过期完整构建报告，以及因报告先被判过期而未到达预期配置异常的断言。不放宽旧检查或改写历史构建证据；不能将全套件写成全绿。

第一次 `verify_flash` 使用 `--flash_size 32MB` 时，esptool 提示它在内存里更新了镜像摘要；该次结果没有作为独立原样校验门禁，也没有改写 Flash 或本地备份。随后改用 `--flash_size keep`，全片原样校验通过，并保留了两次原始日志。后续审计必须使用 `keep`，不能忽略图像转换提示。

首次离线检查还误写了一个不存在的 Python 路径；该调用未启动，随后使用已验证的 Python 3.13 绝对路径重跑审计和测试并确认退出码均为 0。此处作为行动指南更新：复制预检报告中的完整解释器路径，并逐项检查子进程退出码，不能让最后一个成功命令掩盖之前失败。
