# E3f-4a：用进食动画验收电脑播放

更新：2026-11-09。

主人反馈：平静的眨眼与日常待机相近，难以确认电脑请求是否实际播放。验收对象改为现有 `eat.eaf`，保留平静原接线。本轮平静请求已有 `dispatched`，画面记为“难区分”，接续进食验收。

## 设计

现有 `eat` 语义使用 `eat.eaf`，20 fps、单次播放、单眼镜像布局，无 `SetEmotion` 附带动作。`delicious` 是另一语义，目前连接 `Happy.eaf`。

| 接口 | 本轮增量 |
| --- | --- |
| 固件开关 | `DESKBOT_STUDIO_EAT_REQUEST_ENABLE` 默认关闭，依赖现有表情请求 |
| 能力声明 | 在 `expression_semantics` 中按配置声明 `eat`；原字段缺失继续按 `neutral` 解释 |
| 电脑请求 | `operation: eat`，经现有协议发送 `play_expression / semantic_id: eat` |
| 调度与回执 | 原应用主循环调用 `SetEmotion("eat")`，沿用请求编号、有效期、去重、取消与 `accepted`/`dispatched` |
| 工作台 | 新增“播放进食”，显示当前目录中的动画；同会话完整目录与新鲜能力匹配后可发送 |

新版工作台支持旧固件；连接进食固件时，工作台、连接进程和协议校验器一起升级。新能力字段最多声明 `neutral`、`embarrassed`、`eat` 三项，具体值由各自配置决定。单次进食播完后的画面按现有播放器行为观察记录。

数据流：工作台 → 唯一 USB 所有者 → 原请求队列 → 应用主循环 → 原播放器 → 设备回执与人工观察。资源继续使用 E1.18；本轮候选从已验收 E3d-2b 构建，沿用显示 DMA 修复、接收节奏和任务参数。害羞能力独立排期。

## 验证与交付

1. 专项测试覆盖进食/害羞开关的四种组合、旧版兼容、进食语义传递、去重、菜单/语音取消、状态过期、断线重连和目录条件。请求语义继续在锁内按票据复制。
2. 工作台检查按钮、绑定说明和请求；固件双配置核对关闭版基线、开启版差异、内部内存、栈和保护产物。
3. 独立 AI 复核后准备仅 App 的现场计划。读取当前前缀并核对保留备份的整片 32 MiB 设备摘要，保存本轮完整快照；随后写入 App、回读并检查启动。
4. 回主页待机，电脑发送一次进食，主人确认动画，再测菜单往返、对话中/后切菜单、摸头和睡眠唤醒。

进食验收后先用同轮 App 备份恢复 E3d-2b，再接原 E1.45 → 目录重读 → E3f-1 安装链。更多表情合并到后续组合版本。每轮记录设备版本、具体动画、设备回执和主人观察。

现场读取约 25 秒/MiB，备份复用已验证的“新前缀＋整片摘要”流程；已读片段与中断记录保留。

## 当前结果

315 项离线测试通过，独立复跑原测试 314 项及更新后的 9 项部署测试通过；浏览器 24 项通过。关闭版代码与数据匹配 E3d-2b；开启版 App 增加 224 B，内部静态内存仍为 65,136 B，App 余量 1,625,840 B。见[构建与测试](../artifacts/studio-eat-e3f4a/)及[独立复核](../artifacts/studio-eat-e3f4a/review-transfer.json)。

现场计划 `e3c-live-20261109-e3f4a-live2` 已完成 COM4 App 安装。`0x10000–0x460000` 完整回读一致，NVS、保护区及正常启动核对通过；同轮 E3d-2b 完整回退字节已保存。

工作台地址为 <http://127.0.0.1:8775/#connection>。实际目录 36 项，能力为 `neutral`、`eat`；进食请求 `expression-95a1ff2fe04e43ab9ca9e91f47dbe53e` 已收到设备 `dispatched` 回执。首条电脑请求在排队时过期，未发送到设备；本次在状态刚刷新时明确重发，沿用原时间限制。见[现场结果](../artifacts/studio-eat-e3f4a/live-result-20261109.json)。

主人可回主页待机，点击“播放进食”，观察约 4 秒，再测试菜单往返、对话中和结束后切菜单、摸头、睡眠唤醒。圆屏效果与本版日常交互待确认；通过后接续同轮恢复 E3d-2b → E1.45 → 重读目录 → E3f-1。
