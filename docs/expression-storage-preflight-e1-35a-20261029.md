# E1.35a 扩容预检与未来空间

更新：2026-10-29。本阶段只做离线源码、分区、构建和预算审计，没有访问串口、读取设备或写入 Flash。设备基线保持此前验收的 E1.26 observer-enabled App + E1.18 assets。

## 结果

8 MiB `assets` + 后移 `model` 在布局和构建层面通过了 E1.35a：观察器开/关各完成旧布局与候选布局两次隔离构建，共四份产物。每组的 App、ELF、bootloader、原始构建资源、独立模型、OTA 数据和 `sdkconfig` 逐字节一致，唯一布局差异是分区表及 `model` 的新地址 `0xDEC000`。启用版 App SHA-256 与已归档 E1.26 一致。

这证明源码引用的是分区标签，不是把 `assets` 或 `model` 地址写死在 UI/播放器中；不证明实机能成功 mmap。`assets` 是启动早期整区映射，候选地址跨度从 95 个 64 KiB 页变成 129 页。组件的静态检查要求报告的可用 data 映射页大于 128，然后仍要由 `esp_partition_mmap` 实际返回成功；连续 DROM 空间、PSRAM、最大堆块和启动时资源/模型加载仍未测量。

资源与模型的身份也已核实。E1.18 包为 5,538,351 B，SHA-256 `9d12465fe68ef1cfe11bb9cec609199e345408e0ec23451a97ff2b08ef6ba5c1`；其中 `index.json` 仍指向内嵌 `srmodels.bin`（291,069 B）。独立 `model` 构建镜像为 582,107 B。正常路径从 assets 读取内嵌模型；AFE、唤醒词等空模型参数路径仍可能调用 `esp_srmodel_init("model")`。迁移必须同时备份并搬移两者，不能把独立分区当作废弃空间。

## 未来预留规则

- App 继续保留 6,000 KiB；启用观察器的 E1.26 App 为 4,477,280 B，余量 1,666,720 B。协议、表达仲裁和有界缓存每轮都必须检查增量。
- 候选 8 MiB 资源区装入 E1.18 后余量 2,850,257 B。建议活动包软上限先设 7 MiB，保留 1 MiB 给索引、核心回退和兼容增长；这是发布策略，不是固件强制限制。
- NVS 只有 16 KiB，不承载完整外壳目录、动画或历史。稳定迁移后可另评估从候选尾部划出 256 KiB 版本化档案区；当前分配为 0，必须另做磨损、校验、导出和恢复审计。
- 完整母库、角色历史、人格/世界状态、TTS 音频和审阅记录放在电脑端。设备只存有限身份事实、当前资源映射和运行必需模型。
- 候选尾部仍约 1,359,872 B，放不下完整第二 App 或完整第二活动包，因此没有自动 A/B 资源更新或原子布局回滚能力。若未来要求断电原子替换，应重新设计分区/升级机制或评估更大 Flash，而不是继续挤压当前尾部。

## 迁移顺序（下一阶段只生成清单，不直接执行）

1. 重新识别本体、Flash 容量和当前分区；在下载模式下回读并核对旧分区表、App、assets、model、NVS 及新 assets 将覆盖的旧 model/尾部范围。
2. 用 E1.18 精确包和原 model 内容生成版本化 manifest、旧布局精确回退、新布局完整镜像和负向检查。构建生成的 5,889,001 B 原始资源包不是部署输入，不能直接使用其通用 `flash_args`。
3. 保持下载模式，先写入并回读新布局中的 model 与 E1.18 assets，验证边界和摘要；分区表最后提交。顺序纪律不等于断电安全，任何中断都必须通过 USB 下载模式按备份恢复。
4. 启动后记录 assets 挂载、校验、内嵌/独立模型初始化、data mmap free-pages、连续映射结果、PSRAM 总量/最大块和堆峰值，再做对话、菜单、触摸、睡眠/唤醒、DOA 和官方动作回归。没有这些日志，不能接受扩容。
