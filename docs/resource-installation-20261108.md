# E1.45 资源安装与恢复

目标：把已制作的害羞动画装进现有 8 MiB 活动区，保留本轮原资源，支持安装中断后恢复。本页记录固定 E3c-3b 的原实现；当前 E3d-2b 的接续实现按[专用设计](resource-installation-e3d2b-20261108.md)推进。

唯一写入范围：`0x01000000–0x017fffff`，完整 8 MiB。App、分区表、NVS、模型与底座保持当前内容。候选固定为 E1.45，资源包 5,981,260 B；仅把 `embarrassed` 从 `Happy.eaf` 接到 `shy_candidate.eaf`，25 fps。

| 接口 | 输入 | 结果 |
| --- | --- | --- |
| prepare-offline | 已有 32 MiB 快照、设备身份摘要 | 演练计划与原资源；供电脑核对 |
| prepare-live | COM4 新身份和当轮 32 MiB 读取 | 实测计划、备份和保护摘要；读完启动原 App |
| check | 保存的计划和镜像 | 几何、摘要、分区表、原/候选与恢复材料检查 |
| install | 实测计划、匹配的 plan ID | 写资源 → 全片回读核对 → 启动 → 等人工验收 |
| recover | 同轮计划与原资源 | 写回原资源 → 回读 → 启动原 App |

恢复入口独立于候选与构建目录。首次写入前持久保存恢复意图，恢复失败可再次运行；进程中断留下的状态也进入恢复流程。开始安装前重新核对整片，NVS 若因正常运行变化，就重新准备本轮计划。恢复时保留设备当下 NVS，并核对其恢复前后相同。

数据流：冻结候选 + 现场快照 → 绑定身份的计划 → 恢复日志 → 单个资源写入 → 完整回读 → 启动记录。串口仍由唯一 COM4 进程持有。传输复用已审计的 esptool 读取、身份和启动采集，只增加资源范围适配器。

测试：完整安装/恢复；部分写入失败；启动和回读失败；恢复再次中断；候选删除后恢复；身份、分区、摘要和范围不匹配；磁盘持久日志；真实 E1.45 离线演练。实机补测害羞表情、菜单、对话、摸头和睡眠唤醒。
