# E3f-7：常用表情接口

更新：2026-11-10。接续已验收的 E3f-6 节点播放。本轮完成电脑端、固件候选和离线验证，设备沿用 E3f-5 / E1.45。

## 目标与接口

在现有平静、害羞、进食之外，开放五个常用表情。工作台继续用节点预览、改接和发送；设备按实际能力显示可用入口。

| 新入口 | 语义编号 | 当前素材 | 原有附带动作 |
| --- | --- | --- | --- |
| 开心 | `happy` | `Happy.eaf` | `shark_head` |
| 难过 | `sad` | `Sad.eaf` | `shark_head_decay` |
| 困倦 | `sleepy` | `sleep.eaf` | `shark_head_decay` |
| 困惑 | `confused` | `confused.eaf` | `look_around` |
| 惊讶 | `surprised` | `shocked.eaf` | `look_around` |

这五项均沿用 E1.45 目录中的眼部布局、帧率、循环和动作。困倦是表情，系统睡眠仍由原交互管理。

- 固件增加默认关闭的 `DESKBOT_STUDIO_COMMON_REQUEST_ENABLE`，依赖已有表情请求功能；开启后声明并接受这五项。
- 显示查询仍用 `deskbot.studio_display/v1`，可选字段 `expression_semantics` 最多八项；旧设备缺少字段时仅支持平静，显式空列表表示未开放。
- 电脑命令仍用 `operation=<语义编号>`；线协议仍为 `play_expression + semantic_id`，请求、回执和目录格式沿用现有版本。
- 节点仍核对角色接线、素材摘要、布局、播放参数、附带动作和同一会话的真实目录。已验收的三个入口继续可用。
- 页面切换后立即重绘已知状态与按钮；查询仍由现有定时器负责。

## 数据流与依赖

```mermaid
flowchart LR
    N[选择角色与表情节点] --> R[核对接线与设备目录]
    R --> Q[点击后查询最新状态与能力]
    Q --> U[现有 USB 连接所有者]
    U --> A[原应用调度：每次一个请求]
    A --> P[原播放器与附带动作]
    P --> C[设备回执与圆屏验收]
```

依赖：已验收 E3f-5 冻结源码、E1.45 的 37 项目录、E3f-6 角色解析及节点界面。新增入口接入现有调度，沿用请求去重、会话、超时和菜单/对话切换规则。接收线程保存请求，应用主循环调用播放器；读取已接受语义时持锁，调用播放器前释放锁。

## 实现与验证

1. 同步固件允许列表、能力声明、电脑校验和 JSON Schema；生成独立 E3f-7 工作台。
2. 原生测试覆盖八种语义、只开新配置、关闭新配置后的旧三项、旧字段兼容、能力列表及回包长度边界、未知语义、重复请求、排队时输入变化、过期、菜单/对话切换和断线。
3. 集成测试从真实 E1.45 目录与角色节点生成命令，经过电脑连接、生产 C++ 端点和调度，核对素材、布局及附带动作元数据；浏览器验证新增入口与旧设备能力差异。
4. 从冻结 E3f-5 创建独立候选，分别构建新配置关闭/开启版。关闭版的可加载代码与数据对照 E3f-5；开启版核对唯一配置差异、32 MiB Octal、内部静态内存、栈和 App 余量，以及原分区、模型、bootloader 产物。
5. 由另一位 AI 复核设计、改动和证据，归档后接续实机安装与八种表情、菜单、对话、摸头及睡眠唤醒验收。

兼容方向：E3f-7 工作台支持旧设备；安装八项能力固件时使用 E3f-7 入口。旧 8775 / 8776 服务进程继续服务三项能力版本，恢复 E3f-5 后可继续使用。

设计复核已通过；补充配置组合、回包长度和新旧入口切换测试。
