# E3c-3 · USB 只读状态查询

让电脑通过已建立的 USB 会话读取应用与页面快照。固件接口和电脑端编解码、状态管理已实现，178 项离线测试、双配置构建与独立审计通过。当前设备仍运行 E3b 第二版，工作台状态卡片在后续接入。

```mermaid
flowchart LR
    A[电脑建立会话] --> B[发送 state 查询]
    B --> C[原 USB 诊断任务\n核对设备、启动号、会话]
    C --> D[复制 E3c-2 固定快照]
    D --> E[生成只读回复]
    E --> F[电脑校验请求与序号\n显示当前状态，过期后清空]
```

## 查询内容

| 字段 | 含义 |
| --- | --- |
| 应用 | 空闲、聆听、说话等原设备状态 |
| 页面 | 主页、其他已注册页面或未知 |
| 阶段与版本 | 稳定、切换中或未知；应用和页面分别编号 |
| 时间与身份 | 处理查询时的设备运行时间、设备号、启动号、会话及回复序号 |
| 睡眠 | 当前为未知，实际信号来源待确定 |
| 控制能力 | 关闭；这一接口只查询状态 |

请求沿用 `deskbot.studio_session/v1`，操作为 `state`；成功回复使用 `deskbot.studio_state/v1`。拒绝时沿用会话回复，给出设备、启动号、会话不匹配或会话过期等原因。有效查询将会话续期 30 秒。

状态复制结束后再格式化 JSON。新开关默认关闭，依赖 E3c-2 快照；复用原 USB 任务、2 KiB 分帧及 250 ms 回复间隔，回复使用原 1 KiB 缓冲区。原应用、页面所有者、播放器和底座代码保持原样。

## 电脑端规则

- 每次逻辑重连换一个 nonce，清空旧会话、待回复和状态。
- 最多保存一个待回复请求和一份当前状态。
- 请求 2 秒超时；状态按电脑发出查询的时间计龄，2 秒到期后清空。
- 核对请求编号、设备、启动号、会话、序号和设备运行时间；本地计时与设备运行时间分别处理。
- 收到切换中或未知，立即替换上一份状态；界面可直接展示这些阶段。

电脑端由已有串口所有者负责收发。本轮提供 `RuntimeQueryClient`，由调用方传入收到的回复；工作台观察器的串口收发与状态卡片另行接入。

## 验证

46 项查询专项实际编译运行生产 C++ 会话和回复代码，并将原生回复交给电脑端校验。覆盖所有状态、未知与切换中、非法值规范化、会话关闭/过期、断开/重启、分片/粘包、限频、缓冲边界，以及电脑端超时、重放和重连。

加上快照及前序回归，共 178 项通过，见[测试报告](../artifacts/deskbot-studio-e3c3-20261105/offline-validation.json)。

## 构建结果

独立构建和审计通过，完整源码清单共 1,072 项，相对 E3c-2 的固件变化限定在四个文件。构建位于 `tmp/e3c3-state-20261105/`。

| 配置 | App 大小 | App 分区剩余 |
| --- | ---: | ---: |
| 查询关闭，快照与会话启用 | 4,488,144 B | 1,655,856 B |
| 查询启用，快照与会话启用 | 4,489,152 B | 1,654,848 B（约 1.58 MiB） |

启用查询增加 1,008 B，快照存储保持 56 B，新增任务为 0。关闭版代码和数据与冻结 E3c-2 相同，65 个变化字节均为 ELF 摘要和镜像校验。两版的 bootloader、分区表、语音模型与 OTA 初始数据一致。

结果见[构建报告](../artifacts/deskbot-studio-e3c3-20261105/firmware-build-report.json)与[独立审计](../artifacts/deskbot-studio-e3c3-20261105/firmware-audit.json)。本轮未访问串口或刷写设备，E1.42 恢复材料离线核对通过。
