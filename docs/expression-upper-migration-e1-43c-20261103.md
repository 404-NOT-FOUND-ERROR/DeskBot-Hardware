## 采用的布局

| 内容 | 地址 | 处理 |
| --- | --- | --- |
| App、NVS、OTA、PHY、bootloader | 原地址 | 保持原样 |
| 旧资源 | `0x5EC000..0xBC8000` | 留在原位，表中命名为 `assets_prev` |
| 独立语音模型 | `0xBC8000..0xC90000` | 留在原位 |
| 新活动资源 | `0x1000000..0x1800000` | 使用原 E1.18 包，容量 8 MiB |
| 分区表扇区 | `0x8000..0x9000` | 新资源回读通过后最后提交 |

这里复用 E1.35b 留存的资源字节，布局使用 E1.36 上半区方案。E1.35b 原位扩容方案中的模型移动步骤不适用于此布局。

当前包为 **5,538,351 B**，8 MiB 内剩余 **2,850,257 B**。发布软上限为 7 MiB，后续可新增 **1,801,681 B**，另留 1 MiB 余量。母库和角色历史继续保留在电脑。

## 执行与验收顺序

1. 用户方便时完成 E1.43b 的三分钟连续映射、对话切菜单和原 App 恢复验收。
2. 离线实现迁移执行器与恢复入口，模拟各写入阶段中断和校验失败。
3. 实机执行时重新核对身份并保存同轮 32 MiB 完整备份，固定两个受影响区间的原始字节。
4. 写上半区资源并完整回读，再提交分区表扇区；App 和模型沿用现场版本。
5. 核对启动、活动资源地址、模型加载和内存；验收显示、菜单、对话、摸头与睡眠/唤醒。
6. 迁移通过后，进入单个新表情预览、导入和设备验证，再做表达接口及客户端对接。

恢复方案：进入 USB 下载模式，先恢复原分区表并校验，再恢复上半区原字节，核对静态区域和原 App 启动。恢复执行器及中断测试是下一步离线工作。`assets_prev` 是原资源副本，当前 App 没有自动切回它的逻辑。

```powershell
& 'D:\Program Files (x86)\Python\Python 3.13.0\python.exe' scripts/audit-expression-e1-43c-upper-preflight.py --check
& 'D:\Program Files (x86)\Python\Python 3.13.0\python.exe' -m unittest discover -s tests -p test_storage_upper_migration_preflight.py -v
```
