# E3f-3：角色表情整链联测

更新：2026-11-09 · 电脑端联测完成。

目标：把已有模块连成一次可重复的电脑演练：害羞接线从 `Happy.eaf` 换为 `shy_candidate.eaf`，生成 E1.45，安装资源与 App，重读目录，提交表情，检查回执，再恢复原版本。实机按主人方便时接续。

## 实现

```mermaid
flowchart LR
    A[角色接线] --> B[生产 HTTP 生成资源包]
    B --> C[资源与 App 事务]
    C --> D[从安装字节重建目录]
    D --> E[生产 HTTP 解析并提交]
    E --> F[主机控制链路]
    F --> G[固件 C++ 调度与回执]
    G --> H[先恢复 App，再恢复资源]
```

沿用 E3f-2 页面和接口：`/api/package`、`/api/role-expression/overview`、`/api/role-expression/resolve`、`/api/studio/command`。新增整链测试入口，设备 Flash、目录页提供器和底层 I/O 由内存对象代替；解析、打包、部署事务、目录校验、主机控制和 C++ 调度使用现有实现。

目录从安装后的资源字节解析，核对文件摘要、镜像布局、25 fps、循环和蹭蹭动作。接口能力从原版或害羞版 C++ 查询获得。`accepted`、`dispatched` 与圆屏效果分别记录，底座动作仍按事实展示。

资源事务直接使用本轮 HTTP 下载的镜像；目录复用原 C++ 挂载适配器与真实 SHA-256，由共享内存 Flash 的资源切片生成。内存 App 摘要决定使用原版或害羞版原生程序，两版各 1,083 项冻结输入均与构建报告核对。测试目录提供器转送原生生成的条目，同一个设备接口生成会话、目录和显示回复，保持单条在途请求。

## 验证与交付

覆盖正常闭环、重复提交、菜单切换、语音开始、重连、目录缺页或摘要错误、资源失败恢复、App 失败恢复，以及保留当下设置的分层回退。每轮测试使用独立临时目录，结束后自动移除大镜像；保留测试日志、摘要、结果和独立 AI 复核。

14 项集成测试通过：生产 HTTP 下载的 8 MiB 镜像与 E1.45 一致；从安装字节读回 36 项、18 页目录；29 项角色接线均匹配，平静与害羞两个请求入口可用。害羞请求返回 `accepted`、`dispatched`，原生显示入口调用一次。重复提交仍调用一次；菜单、语音和断开会取消待执行请求。

仅 `embarrassed` 改为 `shy_candidate.eaf`，25 fps、循环；镜像布局与 5 种动作保持一致。先回退 App，再回退资源，原字节与当下 NVS 核对通过。圆屏播放与底座动作在实机阶段验收。结果见[验证报告](../artifacts/studio-role-flow-e3f3-20261109/offline-validation-2.json)和[链路证据](../artifacts/studio-role-flow-e3f3-20261109/integration-evidence-2.json)。

使用工具链预检给出的 Offline Python：

```powershell

```

新一轮使用新编号并去掉 `--check`。完整套件需要本机留存的镜像与构建，重新编译测试用原生程序；生成的临时镜像自动清理。
