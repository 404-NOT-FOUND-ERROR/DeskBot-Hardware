# S1d：正式外壳采样准备

2026-11-13。目标是把 S1c 的任务变成一张可接续操作单，完成正式采样后再确认角色绑定。当前电脑端预览在 [8780/#shells](http://127.0.0.1:8780/#shells)，设备沿用 E3f-9d.3。

## 本轮范围

工作台显示当前阶段、下一项任务、独立装配编号和操作提示。每壳先登记 1 次，再独立装回 10 次；取下和未登记布局分别 10 次。确认外壳名称、固定磁铁布局、安装基准和未知对照后，生成现场操作单；导入、评估和绑定草稿沿用现有入口。

主人负责拆装和观察，开发者负责串口交接、采集与导入。当前页显示电脑端准备，不把已有历史数据计入正式验收。

## 接口和数据流

`GET /api/shells/state` 增加 `field_guide`：项目版本、准备项、分组进度、下一项任务和完成条件。准备项保存在项目的 `field_setup`；以 `POST /api/shells/prepare` 更新，参数为 `session_id / revision / layout_fixed / frame_confirmed / unknown_reference`。`unknown_reference` 记录用于对照的未登记布局名称；留空时对应任务显示待准备。

任务与原日志 → 导出当前操作单 → 按任务独立采集 → 原日志导入 → S1a 评估 → 绑定草稿。计算操作单只读取项目，不修改识别参数或设备；准备项更新核对项目版本并原子保存。已有项目无需迁移，缺少准备项时按待确认显示。

采到第一份未知布局数据后，对照名称随这批记录固定。测试另一种未知布局时新建项目；登记、安装确认项仍可更新。未登记对照使用与已登记外壳不同的名称。

完成判定分开显示：采样量到位、评估结果符合预期、角色已选择；正式项目满足三项后提示进入绑定确认。历史演练始终保留原标签。

## 验证和接续

单元测试覆盖旧项目、准备项格式、版本冲突、任务顺序、登记与验证分离、未知对照缺失和锁定、样本不足、评估不匹配及历史标记。HTTP 与浏览器验证准备项保存和重新打开、任务跳转、操作单导出及零设备命令；由另一 AI 复核。

结果：21 项新增测试，加既有 76 项回归，共 97 项通过；26 项浏览器检查通过，设备命令为 0。另一 AI 独立复测 97 项并核查最终页面记录通过。复核发现的对照改名问题已修正并补测。结果见 `artifacts/shell-workbench-s1d-20261113/`。
