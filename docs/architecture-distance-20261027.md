# 与目标链路的架构距离 / Architecture Distance to the Goal

更新：2026-10-27。本判断基于当前 checkout 中的架构、协议、构建报告和既有验收记录；本轮没有连接设备，因此不把先前的硬件验收当作本次实时状态。

## 目标与当前实现

| 目标链路 | 当前落点 | 距离 / 未闭合处 | 下一道验收 |
| --- | --- | --- | --- |
| 可换外壳产生磁场事实 | C61 底座的 XYZ 遥测；S3 有界窗口/置信度识别；`self.shell.identify`、`self.shell.list` 只读查询 | A/B 历史样本曾可区分；底座目前维修状态，固定布局 C、重装/运动/漂移仍未独立验收；档案为 RAM | 底座修复后固定 A/B/C 训练与盲测、移除、重装、运动恢复和断线过期测试 |
| 未知外壳由主人确认 | 外壳识别和角色绑定已有分开的协议/schema 与离线审核 | 设备上没有完整登记/确认 UI 和持久化流程；不应把 `known` 自动当角色 | 明确登记、改名、取消、重复 ID、断电恢复与回滚流程 |
| 识别结果到电脑客户端 | 身体事实与事件接收协议、快照/序号/过期规则已在 `protocol/`；本体有 MCP 按需查询 | 没有本体到正式客户端的生产实时传输适配器、连接管理和线上端到端测试 | 先实现只读出口，做断线、乱序、重放、超时、背压与快照恢复契约测试 |
| 客户端把壳绑定角色与人格 | 角色 Profile/注册表/解析的 schema 和离线 consumer 原型 | 正式客户端、确认交互、持久化和 DeepSeek/TTS 集成不在当前固件闭环内 | 先与客户端共同冻结版本化绑定协议和用户确认状态机 |
| 角色驱动表情、灯光、触摸、动作 | XiaoZhi 官方表达/动作能力仍是设备稳定基线；E1.19 节点工作台可离线预览，E1.20+ 审计映射和资源 | 节点草稿不等于设备可热切换；没有从客户端进入的角色表达命令、仲裁和回执；不得覆盖官方触摸/DOA 所有者 | 建立限白名单、有限速、可取消的表达能力接口；逐项主机/实机回归 |
| 观察现有表情行为再精简资源 | E1.24 静态入口覆盖；E1.26 默认关闭、RAM 有界 `SetEmotion` 调用观察器；E1.27 离线 JSON 导入/节点高亮，并独立展示用户口述摘要 | E1.26 已部署且用户完成本体回归；已有“最近 24 条、`happy`/`embarrassed`/`sleepy` 占多数、其余 `neutral`”的口述信息，但原始 JSON、精确次数和顺序尚未导入；调用不代表 EAF 加载、LCD 播放或动作完成 | 先按四类语义做视觉对照；若需要精确频次与顺序，再由程序保存原始 MCP JSON，之后结合官方路径、视觉预览和实机现象审议映射整理，不直接删除资源 |
| 记录身份与交互反馈 | 有界易失事件环、身体事实和离线记录 schema | 没有长期存储策略、客户端记录上传或隐私/保留策略 | 确认最小记录字段、用户控制和删除/导出语义后再接持久化 |

## 结论

固件端的“身体事实采集与局部识别”已经有实现和协议基础；当前离目标最近的部分是表情资源的离线查看、映射审计和有界调用观察。最大的结构性缺口在两个边界：维修中的底座让外壳识别可靠性缺少完整独立评估，正式客户端与本体之间还没有实时只读传输。角色确认、客户端人格、表达调度和长期记录都是后续能力，不能从 schema/工作台存在推断已接通。

## 建议的顺序

1. **完成语义级观察审阅**：E1.26 已写入 COM4 本体，回读摘要与候选一致，分区表及 E1.18 资源校验通过；用户已验收屏幕、菜单、对话、摸头、睡眠/唤醒和声源跟随。设备已通过语音给出最近 24 条的定性摘要，E1.27 可跳转查看四类当前映射；原始 JSON 的精确次数与顺序仍待程序化导出。
2. **审阅观察结果**：按语义和顺序查看节点工作台，把 `SetEmotion` 调用入口证据与官方事件路由、视觉预览和实机观察对照；它仍不能单独证明 EAF 加载或 LCD 呈现。
3. **再决定是否整理映射**：基于真实调用与逐项视觉审阅提出单语义草案，先离线覆盖/共享引用/容量/播放器审计，再由用户选择，单独构建并实机验证；不据观察器数据直接删资源。
4. **底座修复后复验外壳事实**：使用固定 A/B/C 布局并拆分训练与盲测，再测试无磁铁、重装、移动、断线和恢复。通过之后才定档案持久化。
5. **先打通客户端只读身体事实**：与客户端一起冻结消息、会话/启动 ID、快照、序号、过期、确认和回放拒绝规则；不同时开放动作控制。
6. **最后连接角色与表达**：先主人确认外壳-角色绑定，再接受限的表情/动作请求与完成回执；稳定后再迁移 XiaoZhi 的 ASR/TTS/Agent 到客户端的 DeepSeek/TTS。

每一步先审源和协议、跑离线测试，再构建；硬件步骤单独授权、限制写入分区、完整读回并回归。构建通过或可视化页面正常都不代表实机通过。
