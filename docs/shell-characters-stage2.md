# 阶段 2：外壳关联与离线换角

目标：接通“添加外壳 → 选择完整角色 → 确认关联 → 演练换角”。日常页面使用外壳名和角色名，原采样工具移入高级入口。正式采样按既有记录稍后接续。

## 数据与接口

新增电脑端 `deskbot.shell_characters/v1`：库修订、外壳编号与名称、采样来源引用、完整角色的确认快照。来源保存项目、项目内外壳、设备、磁档案及 archive 摘要；角色快照保存完整角色编号、修订、内容摘要和表达角色版本。一壳保留一条当前关联，多个外壳可选同一角色。角色或档案更新后提示重新确认。

“确认关联”保存主人对角色选择的确认。识别验证、设备同步分别显示状态；未采样也能先保存选择，后续补登记。历史日志仅用于演练。原 S2a 的 `role_id` 仍表示表达角色，本阶段以 `expression_role_id` 明确关联。

| 接口 | 用途 |
| --- | --- |
| `GET /api/shell-characters/state` | 外壳、完整角色、可选采样来源与最近演练 |
| `POST …/save-shell` | 创建或改名，带外壳编号和预期库修订 |
| `POST …/confirm` | 外壳、完整角色及修订、来源及摘要、预期库修订 |
| `POST …/simulate` | 选择两壳及场景，以内存设备回执演练 |
| `POST …/replay` | 从已有项目原日志重识别，展示各窗口外壳与完整角色解析 |

POST 使用同源 JSON 与 `X-DeskBot-Studio: shell-characters-v1`。保存采用单写者、原子替换与修订检查；同值重试返回已保存结果。读取角色、来源、关联时按“采样 → 角色 → 关联库”固定锁顺序取得一致快照。演练结果带输入版本摘要，配置更新后显示需重跑。

## 换角决策与数据流

`识别事实 → 已确认关联 → 完整角色版本 → 表达目标 → 请求 → 首帧回执 → 保存回执`。

离线协调器用显式时间和事件运行：已知外壳稳定后形成目标；说话、转动或内容更新期间延后，连续换壳只保留最后目标；取下和未知保留当前画面并清除未发送目标；未知持续出现时提示登记。默认稳定 800 ms、未知提示 2 s，作为离线初始参数，实机阶段再核定。

断开清除本地在途请求；设备上原请求可能已执行，重连后先读新会话的实际表达与保存状态，再以新观察重新确认目标。状态快照和回执均关联当前连接代次。无数据、未稳定或过期重置稳定计时并清除未发送目标；解除延后时再次检查观察新鲜度，初始上限 1500 ms。首帧与保存分别确认，旧代次、旧请求及过期关联版本留作丢弃记录；重新决策读取最新确认版本。相同表达角色的不同完整角色仍按完整角色版本区分。语音服务标记为后续接入。

来源：场景演练使用明确的模拟信号和内存设备；日志回放重跑既有识别器并逐窗口解析，窗口汇总不充当连续运行时序。二者单独标注，均与真实设备状态分开显示。

依赖：阶段 1 完整角色、SessionStore 原日志/档案、现有识别器。设备命令入口留给阶段 3。

## 验证

单元测试：确认版本、来源失效、重复来源、原子失败、修订冲突；延后与目标合并、取下/未知、转动/更新、断开重连、乱序与旧回执。集成测试：生产 HTTP 保存重开、原日志重识别与完整角色映射。浏览器：完整登记流程、修改关联、错误恢复、演练结果、窄屏及设备命令计数。设计与实现由另一 AI 复核。

设计复核：`product_pipeline_review` 通过，已补重连查询与断流后清除旧目标的处理。

## 交付结果

入口：[我的外壳](http://127.0.0.1:8780/#shells)。先在“我的角色”保存喜欢的角色，再添加外壳、填写名称、选择角色并点“确认关联”。采样来源可稍后补齐；两种外壳保存后，可直接演练换角。原项目从“采样与日志工具”进入。

- 36 项本阶段单元/HTTP 测试通过；角色、原外壳、采样操作单回归分别为 24、21、21 项。34 项本阶段浏览器检查、38 项角色页面检查、26 项采样页面检查通过，桌面与窄屏已核对。
- `product_pipeline_review` 独立复核通过，已修正关联摘要变化后的目标更新与旧连接状态回复，并验证冲突、丢响应和重试恢复。
- 8780 已载入新版，原有 3 个采样项目与 6 条来源可读取；本轮使用独立测试库完成流程，主人角色与外壳库保持原内容。

关联配置保存在 `tmp/deskbot-character-profiles/shell-characters.json`。启动：`scripts/start-deskbot-shell-workbench.ps1 -Preview -View shells`；采样入口为 `-View capture`。专项测试：Python 运行 `-m unittest tests.test_shell_characters -q`，Node 运行 `tests/shell-characters-browser.cjs`。
