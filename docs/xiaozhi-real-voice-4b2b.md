# 4b2b：真实网络与中文语音

2026-11-17。接续 [4b2a 协议联测](xiaozhi-voice-seam-4b2a.md)，本轮先完成电脑端真实音频闭环，再准备设备迁移。

## 本轮选择

电脑已安装中文语音识别与发声引擎。本轮用 Windows `System.Speech` 处理真实音频，采用通用听写；网络和音频接口独立，后续按音质、延迟与部署需求替换服务。生活状态继续由原 Node／SQLite 保存。

先做这一条可复测链路：**中文声音 → Opus → 实际 WebSocket → 中文识别 → 原聊天 → 同一份回答 → 中文发声 → Opus → 接收端 WAV**。模型使用固定回复单独标记；真实模型配置、真机收音和圆屏声音接续验收。

## 接口与依赖

| 模块 | 接口与约定 |
| --- | --- |
| WebSocket 接入 | 小智 `/xiaozhi/v1`，核对固定 token、Device-Id、Client-Id 和协议版本；每个绑定设备仅保留一个活动连接，沿用 4b2a 会话与取消 |
| Opus 编解码 | 16 kHz 上行、24 kHz 下行，单声道、60 ms；真实解码核对每包采样数，PCM 总长与字节数均有上限 |
| 中文识别 | `recognize({packets, audio, signal})`：解码为 PCM WAV，再交通用中文听写，返回实际识别文字和来源 |
| 中文发声 | `synthesize({text, signal})`：将原回答交给已安装中文音色，生成 24 kHz PCM，再编码成 Opus |
| 自动断句 | `auto` 模式用解码后的音量与连续静音结束一句；首次说话前有等待上限，持续说话受 30 秒上限约束。`manual` 沿用明确 stop；`realtime` 接续单独实现 |
| 失败接续 | 静音、断流和处理失败会关闭本轮连接，让设备回到可重新发起的状态；旧回合收尾核对代次 |
| 发送节奏 | 音频按每包 60 ms 发送，等待背压时可取消；结束事件在最后一包提交后发送 |
| 原服务 | 共用一个客户端适配器，固定事件、时间与绑定；本轮独立 SQLite、实验设备、临时端口，输出完成范围保持电脑端联测 |

新增固定依赖：`ws 8.23.0`、`opusscript 0.1.1`，从官方 npm registry 下载并核对 SHA-512；两者无必需传递依赖。保存在本项目忽略的 `tmp/voice-runtime-4b2b/node_modules/`，版本与归档摘要写入依赖锁。Node 使用已核对的 v24.22.1。Windows PowerShell 使用系统绝对路径；语音子进程隐藏窗口，超时与取消会结束子进程。

语音输入、临时音频及服务运行目录按任务隔离。测试用语音合成生成输入录音，实际识别使用通用听写；原始音频与结果在本地保存。后续真人验收使用桌宠麦克风。

## 测试与接续

单元覆盖 WAV 边界、Opus 真实编解码、静音断句、超长输入、协议身份、取消、背压与重连。集成启动实际 WebSocket 和原 HTTP／SQLite，核对识别文字、唯一回答、语音解码、输出来源及旧回合收尾；4b2a 和原客户端测试同时回归。

复测入口为 `scripts/verify-real-voice-4b2b.mjs`：25 项本轮测试、36 项上轮协议测试和 19 项原客户端回归，逐项记录结果及源码摘要。独立启动器已核对健康状态、独立存档和正常关闭。实现与命令见[模块说明](../integrations/client-4b2b/README.md)，结果见[归档](../artifacts/xiaozhi-real-voice-4b2b-20261117/report.public.json)。

真实录音链路识别出“今天我很开心”，原生活库仅增加一轮交流，同一份回答完成语音合成并经网络接收解码。短停顿测试保留两段语音，其中“我想去公园散步”被识别为“果想去公园散步”；后续真人语音验收据此比较服务质量。测试录音由合成生成，首包计时来自电脑本地批量发送，设备实际延迟另测。

后续顺序：**主人绑定与持久恢复 → 设备网络迁移 → 真人收音、发声与日常交互验收 → 常驻部署 → 4b3 日常体验**。正式模型配置、主机和语音服务按质量、费用与部署条件共同确定。
