# E1.43b：连续 8 MiB 映射验证

2026-11-04 更新：设备已迁至 `upper-assets-8m`。当前准备入口、共享映射判断与后续实测流程见 [E1.43b-2](expression-continuous-mmap-upper-e1-43b2-20261104.md)。以下为迁移前记录。

## 目的

验证候选资源区 `0x01000000–0x01800000` 能作为一段连续的 8 MiB 映射使用，并与现有屏幕、语音和菜单共同运行。现有资源继续播放，实际资源迁移在 E1.43c 验收。

## 实现路径

1. 独立诊断开关，默认关闭；关闭版与启用版分别构建并核对产物。
2. 使用单个后台任务，沿用现有诊断输出。任务持有映射句柄，退出路径统一释放。
3. 空闲时建立完整映射，以小块缓冲计算直接读取和映射读取的摘要，与同轮现场备份比较。
4. 保持映射，留出明确的交互测试窗口，采集切菜单、对话、摸头和睡眠/唤醒期间的内存与任务状态。
5. 到期或发生错误时释放映射，核对空闲页恢复，再恢复原 App 并回读。

探针使用固定缓冲、固定任务栈和有限记录；通过原有所有者执行 UI 与音频操作。构建及运行文件放在本工作树独立目录。

## 已实现

固件只增加默认关闭的 `DESKBOT_CONTINUOUS_MMAP_BOOT_EXPORT`、后台任务入口和独立探针头文件。它与 A7、E1.42.3 诊断互斥。关闭版与原 E1.42 比较可执行内容，启用版独立检查诊断符号和保护产物。

- 任务优先级 1、栈 8 KiB；启动后最多等 120 秒，连续三次观察到音频空闲后开始。
- 一次映射 128 页，以 1 KiB 缓冲逐块比较直接读取与映射内容；每 1 MiB 输出一对摘要，每 4 KiB 让出 CPU。
- 持有映射 180 秒，每 10 秒采样一次，共 19 次；记录状态、音频空闲、堆、最大块、历史最低水位、任务栈和 MMU 页数，并核对首尾内容。
- 所有成功及错误路径统一释放映射，再输出结束记录。主机要求完整、有序的成功记录，并与同轮现场备份比较。

| 运行阈值 | 下限 |
| --- | ---: |
| 内部堆空闲 / 最大块 | 16 KiB / 8 KiB |
| PSRAM 空闲 / 最大块 | 1 MiB / 256 KiB |
| 诊断任务栈余量 | 1 KiB |
| 持有时 MMU 空闲页 | 16 页 |

阈值检查每次快照的当前值；全局历史最低水位单独记录。初次映射应恰好减少 128 个空闲页，释放后恢复原页数。交互期间同时观察当前状态和音频活动；屏幕及操作效果由用户验收。

## 执行与恢复准备

`scripts/run-expression-continuous-mmap-e1-43b.py` 提供本阶段专用的 `execute` 和 `recover` 入口，使用 IDF Python。[16 项事务测试](../artifacts/expression-continuous-mmap-e1-43b-20261103/deployment-host-tests.json)通过，设备读写、日志采集和启动均使用模拟实现。

执行时先复核构建、A7 设备身份和完整现场内容，再保存同轮 32 MiB 备份、App 擦除范围原字节及恢复日志。候选 App 补齐到完整擦除范围；成功或异常后恢复原字节，逐字节回读 App，并核对其余静态区域和原 App 启动。NVS 的运行时变化单列。

恢复入口只依赖本轮保存的计划、原 App 和日志；候选文件、构建报告或完整备份缺失时，仍可按原计划恢复。事务测试覆盖写入中断、候选回读错误、日志超时/崩溃、恢复重试、持久记录失败、静态区变化、NVS 变化和重复执行。继承的 A7 测试页写入入口已关闭。

本轮完成了离线准备；新的设备身份、现场备份和 CPU/交互结果在实机轮次取得。

## 验收项目

| 项目 | 通过条件 |
| --- | --- |
| 地址与容量 | 从 `0x01000000` 起一次映射 `0x00800000` 字节，覆盖连续 128 个 64 KiB 页 |
| 内容 | 分块直接读取、映射读取和同轮备份摘要一致；低地址比较沿用 A7 已知图样证据 |

| 交互 | 点击对话、说话中及结束后切菜单、摸头、睡眠/唤醒正常，日志无崩溃 |
| 恢复 | 原 App 擦除范围回读一致、保护区核对通过、正常启动 |

## 实机操作

1. 本体连接电脑并连上原 Wi-Fi，先保持安静，等待 8 个内容块校验完成。
2. 收到“开始 3 分钟测试”提示后，测试点击对话、说话中及结束后切菜单、摸头、睡眠和唤醒。操作顺序可以灵活安排。
3. 映射释放并恢复原 App 后，再确认显示、菜单和摸头；交互结果与 CPU 日志分别记录。
