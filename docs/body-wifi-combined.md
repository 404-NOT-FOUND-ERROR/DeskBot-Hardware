# 身体联网合并版

2026-11-21。目标：同一 App 同时接通 Wi-Fi 摸头和表情，保持小智语音、双角色、逐素材镜像、菜单与睡眠。合并能力已随 E3f-9d.7 安装，主人反馈当前版本一切正常。[当前交付](body-network-workbench.md) · [日常后台](body-daily-service.md)。下方保留 E6 离线准备记录。

## 接口、数据流与依赖

| 方向 | 接口与结果 |
| --- | --- |
| 摸头 → 客户端 | 沿用 `POST /api/hardware/head-touch`；设备、启动、固件和手势时间确定事件编号，保存后返回 204 |
| 客户端 → 表情 | 沿用 `POST /api/hardware/expression/exchange`；原聊天与输出队列产生平静/开心，设备交给原角色播放器并回传结果 |
| 共同运行 | 两个 HTTPS 监听、独立凭证、同一客户端进程与 SQLite。单个 App 摘要同时登记到两个接口 |

`三连触 → 原触摸队列 → 共享网络任务 → 原输入/身体感知/记忆事务`。

`原交流 → 原输出队列 → 共享网络任务 → 应用调度队列 → 原角色播放器 → 原输出回执`。

共享任务只有一份 6 KiB 栈，每次处理一个请求。两条链路各自保留重试时间，轮流处理同时就绪的请求；摸头等待重试时，表情继续轮询。HTTPS 超时沿用 3.5 秒；图形、触摸与应用回调只复制状态或排队。显示沿用 N32R16、20 MHz 和原资源。依赖原 Wi-Fi/时钟、触摸队列、应用调度、角色播放器及客户端两个接收模块。

## 实现与边界

1. 两个模块提供“初始化”和“一次处理”入口，原专项任务继续可用。共享任务复用这两个入口，串行执行网络请求。
2. 摸头保留八项队列、五分钟过期和原编号防重。表情保留三秒设备窗口、三十秒总时限、角色绑定、USB 会话及菜单/对话/睡眠优先级。
3. 新构建入口组合冻结基线与两个本地配置，核对两个接收配置使用同一设备和网络；输出同一固件摘要。安装只涉及 App，沿用已有回读与恢复流程。
4. 客户端启动器支持两份配置。先在隔离存档联测摸头和原聊天输出的共存、重开、防重与独立凭证，再准备正式存档接续。

## 测试与归档

- 单元：两条链路同时就绪、单侧退避、连续摸头、到期与空闲调度；初始化失败、原触摸顺序及表情回执继续回归。
- 集成：真实 HTTPS 与同一 SQLite，同一设备/固件同时完成摸头入档和聊天表情回执；重开后保持事件和命令编号，原触摸记录各一条。
- 构建：单任务、App 容量、内部静态内存、有效配置与六项保护产物；保留原专项 App 和合并版的离线安装/回退计划。
- 实机：平静/开心交替、三连触入档、服务重连、菜单、对话中及结束后切菜单、睡眠唤醒。主人方便时统一反馈。
