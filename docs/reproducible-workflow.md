# 可复现开发与刷写流程

## 每轮改动

1. 固定上游提交和目标芯片，记录源码差异。
2. 运行不接硬件的协议、状态和资源校验。
3. 在独立目录构建；确认 App 大小、分区余量、资源和语音模型边界。
4. 明确选择 COM 端口并先执行只读芯片识别。
5. 只写本轮允许的分区；默认不擦除 Flash、不覆盖 NVS、不改 C61。
6. 回读写入范围并比较 SHA-256，保存启动日志。
7. 用户完成与官方能力相关的人工回归；失败就回退，不在失败镜像上继续叠加。

## 公开仓库安全边界

禁止提交：

- 完整 Flash 或 NVS 镜像；
- Wi-Fi、DeepSeek、Coze、OpenAI 或 TTS Token；
- 含芯片 MAC 的运行日志；
- ESP-IDF `build/`、`managed_components/` 缓存和编译对象；
- 只在本机有效的绝对路径。

构建依赖通过上游提交、manifest 和补丁描述；本仓库不分发一个无法辨认边界的“全片烧录包”。

## 失败处理

构建成功不等于实机成功。若出现 UI 卡死、刷新等待、触摸失效或电机异常，立即停止增量，保留日志，恢复官方 Stock 参考，再从单一功能重新开始。
