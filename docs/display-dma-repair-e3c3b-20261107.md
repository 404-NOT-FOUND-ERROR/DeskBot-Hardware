# E3c-3b 菜单显示修复

日期：2026-11-07 · 状态：独立复核、离线测试、构建、COM4 App 回读与菜单实机验收通过。

## 现象与依据

E3c-3a 查询开启版联网后，滑菜单时画面停在主页；点击已能发出木鱼声，对话继续。页面和触摸已切换，像素更新失败。

19:51:58.406 日志记录主页切到木鱼页；41 ms 后 SPI 报 DMA 发送缓冲分配失败，44 ms 后报告像素排队失败。冻结的 ST77916 1.0.1 驱动忽略了 `tx_color()` 的错误，仍返回成功。上层因此可能等待不会到达的完成通知。原始日志与人工结果分别归档。

板级配置原为 5,760 B；ESP-IDF 为它准备两个 4,092 B 的 DMA 描述符，因此总线单笔上限为 8,184 B。实际临时 DMA 缓冲按每笔事务的发送长度及对齐要求申请。菜单的 8 行像素块为 5,760 B，日志没有记录失败申请的实际长度。候选将上限设为 4,092 B，使该像素块分为 4,092 B 和 1,668 B 两笔。联网记录的内部空闲内存最低为 25,959 B，历史最低值为 13,288 B；最大连续 DMA 块尚未测量。查询开关只增加 8 B 静态数据，现有证据还不能将问题归因到查询逻辑。

## 实现范围

从已保存的 E3c-3a 查询开启版源码派生，形成独立候选：

1. 板级 SPI 单事务上限调整为 4,092 B，保留深度 2；每次 DMA 临时申请更小。
2. 用带版本与摘要的依赖补丁，让 ST77916 `draw_bitmap()` 返回 `tx_color()` 的实际结果。历史组件保留原样，补丁只在候选构建副本应用。

## 接口、数据流与依赖

接口沿用 `esp_lcd_panel_draw_bitmap(...) -> esp_err_t`，错误原样返回。菜单路径为 LVGL → 显示适配器 → ST77916 → SPI；发送成功由原完成回调结束刷新，发送失败由适配器已有错误分支结束等待。表情路径沿用 `dummy_draw_blit()` 的返回值处理。

依赖固定为本次冻结源码、ST77916 1.0.1、ESP-IDF 5.5.5 和原 LVGL 适配器。PSRAM 像素经原有内部 DMA 副本发送；部分分块排队后失败时，已排队副本由原 SPI 事务回收。PSRAM 直传另行评估。

## 测试与交付

- 单元：真实驱动函数分别注入参数发送失败、首块/中途/末块像素失败及成功，检查返回值和下一次发送恢复。
- 集成：真实适配器相关函数连接模拟 SPI，验证菜单刷新与表情发送的成功/失败完成路径；旧驱动应复现错误被吞。
- 构建：核对冻结输入、唯一代码差异、App/内部内存与保护产物；候选和恢复材料分别保存。
- 实机：联网后菜单往返、对话中及结束后切菜单、摸头、睡眠唤醒；记录 SPI 错误、DMA 最大连续块和屏幕效果。

离线专项测试 4 项通过：冻结版原生夹具 62 条断言，补丁版 65 条断言；App 构建为 4,489,232 B，配置及受保护产物与 E3c-3a 一致。主机测试模拟发送队列的内存分配失败，没有运行芯片堆分配器。候选仅写入 COM4 App 分区 `0x10000–0x458fff`，SHA-256 `180aa8cbcc98e3d5b95329175ff2e3f2ee1d35f806b03cbe0778aa2fc2d0f42a`，esptool 回读校验通过；其他分区未写入。启动、菜单往返、对话期间切页、摸头和睡眠唤醒实机验收通过，详见[写入记录](../artifacts/display-dma-repair-e3c3b-20261107/device-write.json)与[人工验收](../artifacts/display-dma-repair-e3c3b-20261107/manual-verification.json)。
