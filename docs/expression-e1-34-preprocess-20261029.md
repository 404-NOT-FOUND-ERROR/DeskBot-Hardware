# E1.34 候选预处理、布局与时序审阅

本轮继续 E1.33 的 `shy` 研究候选，完成无损重编码实验，并做出可放入现有分区的单眼裁切版本。**设备及正式映射未改变；候选尚未接线、未刷写、未实机验收。**

## 结果

| 方案 | EAF 字节 | 追加后的包字节 | 6,144,000 B 分区余量 | 结论 |
| --- | ---: | ---: | ---: | --- |
| E1.33 原始完整脸 | 717,402 | 6,255,606 | -111,606 | 原稿保留，不能直接追加 |
| 本轮最小无损重编码（13 项内） | 733,356 | 6,271,560 | -127,560 | 像素相同，但比原稿更大，不采用为压缩成果 |
| 单眼裁切研究候选 | 443,181 | 5,981,385 | 162,615 | 容量通过；构图和时序适配仍待审阅 |

13 项实验覆盖编码 `0/1/3/best`、块高 `16/32/64`，另加 `best/32` 不共享重复存储的对照。所有实验保持 8-bit、360×360、188 个图像时间轴条目和 25 FPS，逐帧 RGBA 序列 SHA-256 完全一致。共享重复帧只减少存储，不减少时间轴条目；本轮无损重编码没有得到比原始编码更小的结果，不代表穷尽了所有无损算法。

单眼方案裁切框为 `(x=10,y=90,w=160,h=200)`，不缩放、不量化保留区域，再使用官方 `eye_anim` 的左侧定位与自动镜像布局。保留区域的全部 188 帧像素与原稿对应区域一致，但右眼改由左眼镜像生成；与原始完整脸相比，188 帧构图均有区别，不能称为整幅动画的无损替换。裁切后约小 38.2%，这是结构适配的结果。

容量从完整 E1.18 回退镜像重建：当前包 5,538,351 B，余量 605,649 B。每个候选只在 RAM 中做新增成员和索引投影；现有非索引成员逐字节一致、现有语义条目一致，打包后重新解析通过。`index.json` 重新序列化带来空白变化，所以“文件表和索引的净变化”为 -147 B；这不是通用的负开销，也不能直接用于其他映射方案。正式单语义映射会重新计算实际包大小。

## 播放器与时序

- 对保留的完整脸重编码与单眼裁切两个候选，复用已锚定的官方 C 播放器 DLL；源文件、harness 和 DLL 哈希均与 E1.33 一致。
- 每个候选分别跑 full-screen 与 eye_anim 的 188 帧，合计 **752 次逐帧比较，零像素差**；内存保护、释放和 `[50,150)` 局部循环计时检查通过。这里的零差异指 C 渲染与各自候选的独立参考合成一致，不代表裁切与原完整脸相同。
- 其余 12 项搜索结果只有主机解码、原像素序列与包容量审计，没有冒称经过 C 全帧或设备验收。
- 新增默认产品播放检查发现：研究 EAF 只有 188 个 `_S` 图像条目，没有官方资源常见的尾部 `_C` 元数据。当前播放器将默认终点钳制到 `count-1`，却把终点当作排他边界，所以默认只调度图像 `0..186`，第 `187` 帧不进入计时播放。已保留完整 C trace；下一阶段应从资源端适配尾部元数据，并复验 188 帧都被调度，保持官方播放器不变。
- 仅把 FPS 改成 15/20/30 不改变 EAF 字节，不节省空间，只改变动画速度。报告按原帧数计算真实时长，不把它伪装为已执行抽帧。25 FPS 的完整原始时间轴为 7.52 秒；`[50,150)` 图像区间是 2–6 秒，官方 C 循环完成时还保持最后图像一个计时 tick。
- 产品索引依然只有 `loop/fps`，不能直接配置局部循环端点。此问题与尾部元数据是两个独立限制。
