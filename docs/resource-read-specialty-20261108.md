# 资源读取专项

更新：2026-11-08 · 状态：自动诊断与恢复通过，联网复测和日常交互待完成。

目标：核对上半区 8 MiB 的实际内容、连续映射及资源播放，并保留当前已验收的 E3d-2b。

本轮复用已审计的 E3c-3b 诊断镜像，固件保持原字节。电脑执行器按当前 E3d-2b 保存恢复范围，直接运行诊断，完成后恢复本轮原 App。旧 E3c-3b 工具和报告保留。

## 接口与依赖

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `prepare` | 已安装 E3d-2b 事务、用户验收、原诊断镜像 | 刷新现场前缀、整片设备摘要核对、当轮快照和恢复计划 |
| `check` | 当轮计划及固定构建证据 | 离线核对候选、恢复字节与资源参考 |
| `execute` | 同轮计划编号 | 自动诊断、完整 App 回读、其余区域摘要、原 App 恢复与启动 |
| `recover` | 当轮快照、原 App 与日志 | 独立续做原 App 恢复 |

复用 `studio_app_deployment` 事务、既有 COM4 传输、`storage_continuous_mmap` 解析器和 E3c-3b 固定构建。写入范围为 App 的 `[0x10000, 0x460000)`；恢复覆盖完整扇区并集。当轮 NVS 只读取并单列比较。

数据流：核对当前版本 → 保存现场恢复字节 → 安装原诊断镜像 → 校验 8 个区块、19 次采样和映射释放 → 自动恢复 E3d-2b → 重新核对真实目录与表达请求。

## 验证与交付

自动诊断检查读取与映射内容一致、页数恢复、内部堆、PSRAM 和任务栈。诊断的三分钟由工具自动运行。

日常交互在恢复后的 E3d-2b 验收：原播放器持有资源映射，主人方便时测试菜单、对话、摸头和睡眠唤醒，统一反馈。记录分别标明自动诊断和正式播放交互的 App 身份与结果。

电脑测试覆盖错版本、现场变化、恢复范围、读取与写入失败、诊断失败、恢复中断后重试，以及候选删除后的独立恢复；生产适配器另核对命令、回读与启动日志。执行前由另一位 AI 复核。

完成后接 E1.45 单表情替换。当前版本的[资源安装设计与输入核对](resource-installation-e3d2b-20261108.md)已完成，下一步实现 E3d-2b 专用适配。

## 本轮结果

- 60 项电脑测试及独立代码复核通过。实机的 21 项诊断检查通过：8 个区块、19 次采样，连续映射保持 180,059 ms；读取与映射摘要均与本轮 8 MiB 快照相同。
- 可用映射页数为 189 → 61 → 189，映射已释放。采样最低内部空闲为 47,591 B，最大连续内部空闲最低为 31,744 B，探针栈最低余量为 3,224 B。
- E3d-2b 的 4,521,984 B App 扇区并集已逐字节恢复，其余静态区域摘要一致，5 条周期身份与正常启动通过。NVS 的 67 个逻辑项均保留，仅 `phy:cal_data` 更新。
- 恢复后工作台确认了同一次启动的设备和 App 身份。设备处于 `wifi_configuring`，目录读取未完成，记录为 `catalog_unavailable`；本轮表情请求发送数为 0，USB 已断开。主人选择先做离线部分，联网目录、平静回执和日常交互接续补测。

自动采样期间设备处于配网状态。日常交互在恢复后的 E3d-2b 上按菜单、联网对话、摸头和睡眠唤醒验收。
