# E3f-9d：手动启用角色与保存

日期：2026-11-12。目标：工作台启用原角色或圆团，设备执行对应表情并记住选择，形成可验收的双角色闭环。

## 实现路径

草稿生成双角色包 → 安装 App 与资源 → 重读设备角色目录 → 点击启用 → 应用队列切换 → 首帧处理回调后保存 → 工作台显示已生效。编辑草稿、已装包、选择目标和实际播放角色分别显示。

沿用唯一 USB 所有者和现有会话。新增 `role.query` 及 `role.activate.<index>.<graph_sha256>` 会话操作；索引来自本次设备目录，完整摘要绑定包版本。回复 `deskbot.studio_roles/v1`，包含图摘要、最多四个角色编号、目标、实际播放角色、阶段、暂停原因、保存结果和本次启用状态。请求、设备、启动与会话逐项关联；同一启用请求重复到达只返回原结果。

播放和 Flash 保存由原应用队列执行。USB 任务只解析、校验会话、读取有界快照和排队。先释放状态锁，再调用调度或播放器；GFX 回调继续只排队。重连取消尚未执行的旧请求，已经进入播放器的请求继续完成，并由新会话查询实际结果。

设备以独立 NVS 命名空间 `studio_role` 保存一条版本化选择，绑定角色编号和图摘要。以图摘要、角色和启用代次核对新角色首帧处理回调后提交保存；圆屏效果由实机验收确认；同角色保存重试保留当前播放，相同已保存选择不重复写入。重启后按已装包核对保存记录，包变更时采用包内默认角色。保存失败明确显示“已切换，待保存”，允许主人再次点击保存。

电脑在同一串口调度中穿插角色查询；保持原查询间隔与单条在途约束。角色页保留现有动画节点，在顶部增加设备角色卡和六项实际播放按钮。草稿修改后显示“待生成 / 待安装”，已安装包按设备摘要核对。安装与回退复用现有 App、资源事务，分别保存当轮原字节。

## 睡眠接点

核对目标板源码后，当前 `EspS3Cat` 没有系统睡眠计时器或进入/退出回调；睡眠计时页面、困倦动画和芯片睡眠分别处理。本版接通已有 `SetPowerSaveMode` 入口并回报实际调用状态，未收到调用时维持未知。将来增加系统睡眠时沿用同一入口。

## 验证与验收

单元：目录/摘要/索引、重复和冲突请求、会话变化、队列过期、首帧完成、保存失败与重试、重启恢复、包变更。集成：真实角色包与 C++ 播放器、USB 会话往返、生产 HTTP、浏览器双角色状态。构建：关闭/开启对照、原分区输出、App 与内部内存预算、源文件和依赖摘要。设计、代码和结果由另一 AI 复核。

安装后通知主人直接测试：两角色各播放开心、难过和害羞；连续切换两次；重启检查选择；菜单往返五次、对话中及结束后切菜单、摸头和睡眠唤醒。主人统一反馈，无计时窗口。

下一步：固定布局外壳重复拆装评估与绑定 → 复用角色启用接口自动切换 → 接人格、声音和动作。

独立设计复核已完成：USB 查询读取有界状态镜像；保存使用返回错误的 `nvs_*` 接口；实际播放角色按当前片段归属计算；快速新请求终止旧目标的等待状态。

启用请求沿用电脑请求编号末尾的递增计数；设备缓存最近 16 个结果，并拒绝已过期编号。长会话可持续切换，旧请求不会再次执行。
