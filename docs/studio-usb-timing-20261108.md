# 工作台 USB 查询时序

目标：沿用已验收 E3c-4b 的显示与 USB 接收节奏，让工作台完成查询，再接入单个平静表情。

## 接口与数据流

浏览器 → 本机桥接 → 唯一串口 worker → USB 会话 → 设备回复 → 关联核验 → 工作台状态。沿用现有请求、显示、目录与表情协议；进程间快照增加本机单调时钟时间，桥接层计入传递耗时。

| 时间 | 规则 |
| --- | --- |
| 查询与表情首回执 | 从发送开始等待最多 8 秒，包含 USB 写入 |
| 状态有效期 | 从收到完整且关联成功的回复起算 2 秒；`age_ms` 表示距该回复的时间 |
| 下一次显示查询 | 收到回复后间隔 1 秒；每次只有一条在途请求 |
| 目录 | 读取期间连续逐页请求，结束或失败后补一次显示查询 |
| 表情排队 | IPC 读线程收到完整命令并入队后最多等待 2 秒；主循环处理时沿用该时刻，发送前核对状态与会话 |
| 设备执行 | 保留完整请求到达后的 2 秒期限；从首次受理回执起独立等待终态 3 秒，重复受理沿用原时刻 |
| USB 写入 | 最多 7 秒；平静请求约 531 B，按当前接收节奏约需 5.3 秒 |
| 本机命令确认 | 最多等待 10 秒，覆盖 2 秒排队、7 秒 USB 写入及调度 |
| 会话 | 保留从请求发送时间保守计算的 30 秒租期 |

设备 `at_ms` 用于顺序核对；状态年龄表示电脑收到回复后的时间，设备采样年龄未做跨时钟推算。快照生成时捕获时间，桥接核对当前 worker、未来时间与时间顺序，再累加传递延迟。缓存过期时界面显示等待下一次查询。迟到回复只关联原请求；表情超时保留请求记录，每次点击只发送一次。

## 实现与依赖

集中定义时间常量；查询客户端负责请求和缓存；控制状态机负责分页、表情和调度；worker 负责串口和时间记录；桥接负责本机命令及快照年龄。沿用原串口写入方式、固件每 10 ms 读取一次及 4,092 B 显示分块。

## 验证

单元测试覆盖 2.7 秒会话、3.2 秒显示查询、2 秒缓存边界、8 秒请求边界、慢目录分页、租期、重放、断线与时钟回退。集成测试覆盖写入阻塞、部分写入、进程间延迟、命令排队过期、首回执和受理后终态；生产 worker 再做 COM4 只读查询，归档时序及独立复核。

后续：平静表情与回执 → 真实目录 → 资源映射专项 → E1.45 害羞资源与角色接线 → 更多表情和动作 → 外壳角色绑定 → DeepSeek/TTS 客户端。

## 结果

电脑时序已完成，最终 183 项针对性测试与 49 项浏览器检查通过；此前完整回归 1,348 项，1,346 通过、2 项跳过。真实工作台链路连续读取 3 次显示状态，重连后再读取 1 次；同一次启动、两个独立会话、6 条请求与回复均完整关联。显示查询约 3.34–3.41 秒。历史报告、首次 HTTP 测试错误及通过的重试均已保留。
