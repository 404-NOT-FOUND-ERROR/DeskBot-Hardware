# E3f-1：离线安装准备

更新：2026-11-09。

目标：为“工作台点击害羞 → 圆屏播放新动画”准备可检查的 App 安装包与原 App 回退材料。当前日常交互已复测通过；平静请求收到两条回执，实际画面由主人回家后确认。

## 本轮范围

离线准备按实际安装顺序演练：E3d-2b / E1.18 → 安装 E1.45 资源 → 安装 E3f-1 App。设备继续运行现有版本。

App 计划以 E3d-2b / E1.45 为起点，只覆盖 App 的完整擦除范围。回退恢复同轮原 App；E1.45 资源继续保留。资源本身的回退由已有资源安装事务处理。

## 接口与数据流

| 入口 | 输入 | 输出 |
| --- | --- | --- |
| 离线准备脚本 | 留存 E3d-2b 快照、E1.45 资源与已构建 E3f-1 | 内存中的模拟安装状态、App 计划摘要和恢复顺序 |
| `check_app_plan` | 模拟计划与构建证据 | 版本、容量、范围、原资源和恢复核对 |
| `check_recovery_plan` | 已保存原快照与计划 | 独立恢复核对；测试在移除候选文件后重新加载 |

留存快照 → 校验 E3d-2b / E1.18 → 在内存中替换为 E1.45 → 固定 App 计划 → 模拟安装、失败恢复与重复恢复。

依赖已有 App 事务 `studio_app_deployment`、资源安装事务和已复核 E3f-1 双配置构建。准备结果保存摘要；测试用的快照随隔离目录清理。实机安装使用后续当轮设备快照与部署入口。

## 验证与交付

- 单元验证：候选身份、原 App、分区表、E1.45 资源、完整擦除范围、路径与计划来源。
- 集成验证：生产事务配合内存设备，覆盖安装成功、部分写入、回读失败、启动失败及原 App 恢复。
- 恢复验证：移除候选与构建来源后仍能核对原材料；保留资源与设备运行后更新的 NVS。
- 离线计划明确标记来源与用途，现场准备另建计划。

执行：Offline Python 运行 `scripts/validate-studio-e3f1-deployment.py --attempt <新编号>`；Build 环境运行 `scripts/prepare-studio-shy-e3f1-offline.py`，先核对双配置构建来源，再生成顺序计划。结果见[交付摘要](../artifacts/studio-shy-e3f1/deployment-result.json)、[事务测试](../artifacts/studio-shy-e3f1/deployment-validation-4.json)和[独立复核](../artifacts/studio-shy-e3f1/deployment-peer-review.json)。

后续：平静画面确认 → 当前版本安装 E1.45 → 重读实际目录 → 准备并安装 E3f-1 → 害羞动画和日常交互验收 → 角色表达映射。
