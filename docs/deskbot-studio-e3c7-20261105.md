# E3c-7 · 工作台与桌宠联调

本轮把 E3c App 接入 E3c-6 工作台，验证状态查询、一个平静表情和设备回执。

首次联调停在状态就绪阶段，尚未发送表情。原因是 USB 接收端使用了主控制台路径，而当前 IDF 将 USB 辅控制台注册为 `/dev/secondary`。旧 E3c 已精确恢复为 E3b；修正版在独立目录构建，接收任务新增 4 项实际 C++ 回归检查。完整离线套件运行 1,206 项：1,204 项通过，2 项条件跳过。

## 使用

打开[本机工作台](http://127.0.0.1:8766/#connection)，刷新页面。连接本体并启用状态查询后，应用、页面、播放器三张卡片会更新；设备处于待机主页时可以点击“播放平静”。回执依次显示“已受理”和“已提交播放器”。

平静沿用当前资源 `winking.eaf`。回执确认播放入口已被调用，圆屏效果与触摸、对话、菜单、睡眠唤醒一起验收。实际睡眠状态显示为未知。

## 部署与恢复

| 项目 | 本轮范围 |
| --- | --- |
| 目标 | COM4，ESP32-S3 N32R16 |
| App | 4,510,432 B，分区余量 1,633,568 B |
| 写入 | `0x10000..0x45E000`，4,513,792 B App 擦除范围 |
| 资源 | 沿用 E1.18，活动区 `0x1000000..0x1800000` |
| 回退 | 本轮原 E3b 第二版字节；此前已验收 E1.42 恢复材料继续保留 |

入口为 `scripts/deploy-deskbot-studio-e3c.py`，分为 `prepare`、`install`、`restart`、`recover`。使用串口 IDF Python；HTTP 联调验证器使用 Offline Python。恢复前在工作台断开观察，再按本轮 run-label 执行 `recover`。恢复独立读取原字节和计划，输出新的恢复结果。

首次整片只读采集在 USB 重连时超时，原 App 随后正常启动。新一轮读取当前前缀，并用整片设备摘要核对此前完整 E3b 快照；备份来源、现场 NVS、失败日志与每轮结果分别保存。

`tmp/e3c-live-20261105-neutral2` 保留首次部署、失败联调和成功恢复的记录。修正版采用新的构建目录和部署编号。构建入口为 `scripts/build-deskbot-studio-e3c7-firmware.py`，独立审计入口为 `scripts/audit-deskbot-studio-e3c7.py`。
