# E3f-1：电脑播放害羞表情

状态：离线实现、232 项回归、24 项浏览器检查及双配置构建通过。设备保持 E3d-2b / E1.18；本轮交付为待安装候选。

目标：工作台点击“播放害羞”，通过现有 USB 会话交给原应用主循环，调用 `SetEmotion("embarrassed")`。资源决定画面：E1.18 对应 `Happy.eaf`，E1.45 对应 `shy_candidate.eaf`。该入口同时沿用原有蹭蹭动作 `CAT_NUZZLE`；页面说明动画和附带动作。

## 接口与数据流

| 接口 | 约定 |
| --- | --- |
| 显示查询 `deskbot.studio_display/v1` | 新增可选 `expression_semantics`，最多两项：`neutral`、`embarrassed`；字段缺失按旧版 `neutral` 处理，空数组表示均不支持，未知值、重复值及错误类型为无效回复 |
| 电脑命令 | `operation: embarrassed`；设备、启动、会话和命令编号沿用现有格式 |
| 设备请求 `deskbot.expression_control/v1` | `play_expression / semantic_id: embarrassed`；有效期、顺序与去重规则沿用现有实现 |
| 设备回执 | 沿用 `accepted` 和 `dispatched`；后者表示已调用原播放器入口，动作完成仍由底座独立报告 |
| 固件开关 | `DESKBOT_STUDIO_SHY_REQUEST_ENABLE` 默认关闭，依赖现有表情请求；开启后声明并接收害羞能力 |

点击 → 电脑核对最新显示能力与主页待机 → 唯一 USB 进程 → 原请求队列 → 应用主循环再次核对状态 → 原播放器 → 关联回执。

目录说明“装了什么”，能力说明“允许请求什么”。按钮读取同一设备会话的完整目录，显示当前动画；角色接线分析仍逐项比较资源、布局、帧率、循环和附带动作。请求的固定命令目录 `42a6…` 沿用原协议；实际资源目录摘要由设备目录单独提供。

兼容方向为新工作台连接旧固件。关闭版不输出新能力字段；旧工作台按原方式连接旧固件。

## 实现与依赖

- 固件从冻结的 E3d-2b 来源构建，只改能力声明、允许的表情和调度参数；沿用显示 DMA 修复、每轮一次 USB 读取、10 ms 间隔及原任务参数。
- 调度时核对同一 ticket，并在锁内从已接受请求复制语义到固定局部数组，锁外调用播放器。`Begin` 为提交点；提交前切菜单、开始对话、断开会话或请求过期沿用原取消路径，提交后完成本次调用。
- 电脑沿用 `ControlLink`、`ControlBridge`、角色分析器与工作台；只在新鲜回复明确支持害羞时发送。发送前再次检查能力，读取目录期间等待完成。
- 工作台按钮与角色分析需要同会话的完整目录；底层固定语义请求按最新显示能力执行。播放已经排队或执行时，目录读取等待该请求完成；真正发送前再核对目录读取状态。
- 旧设备仍可播放平静；新按钮显示接入步骤。语音与触摸沿用原表情映射。

## 验证与交付

1. 单元测试：能力字段、旧回复兼容、未知/重复能力、忙碌、过期、断线、重复点击，以及相同编号更换语义的冲突。
2. 集成测试：生产 Python 请求 → 原生 C++ 会话与调度 → 实际语义参数与回执；覆盖菜单、语音和超时取消。
3. 工作台测试：按钮、实际资源名称、请求内容、断线禁用、角色接线分析；使用内存设备。
4. 固件双配置构建：关闭版复现 E3d-2b，开启版核对范围、内存、任务与保护产物；只准备候选。
5. 独立 AI 复核源码、测试和构建记录。本轮使用离线环境。
