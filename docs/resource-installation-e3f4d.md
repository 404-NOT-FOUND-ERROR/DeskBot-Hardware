# E3f-4d：在已验收布局版上安装新资源

更新：2026-11-10。

## 目标与范围

E3f-4c 已获主人验收。本步沿用该 App，把 E1.45 资源装入现有 8 MiB 分区；害羞改用 `shy_candidate.eaf`、25 fps，进食继续居中且不镜像。随后重读真实目录。害羞电脑播放入口在下一增量接入。

## 接口与数据流

| 入口 | 输入 | 结果 |
| --- | --- | --- |
| `prepare-offline` | 上轮已核验安装记录与 E1.45 镜像 | 绑定 E3f-4c 的演练计划 |
| `prepare-live` | COM4 身份、当前配置区和全片摘要 | 本轮完整快照、原资源与计划；保持下载模式接续安装 |
| `install` | 本轮计划与计划编号 | 写资源、完整资源回读、其余区域核对、原 App 启动 |
| `recover` | 本轮快照、原资源与日志 | 恢复 E1.18，保留当前 NVS，启动 E3f-4c |

数据流：已验收 App → 现场备份 → 资源事务 → 启动同一 App → 新会话重读目录 → 核对害羞接线与进食布局。

复用资源事务、COM4 传输、启动身份解析和工作台唯一串口所有者。计划新增独立 E3f-4c 标记；旧入口保留原版本核对。写入范围为 `0x1000000..0x1800000`。参考镜像来自上轮安装快照与候选 App 的审核结果，原始记录保留。

现场准备读取当前 64 KiB 前缀并核对全片设备摘要。写后实际读取完整 8 MiB 资源区，再与保留的其余区域组合核对全片摘要；每次记录方法和范围。中断恢复时同样读取当前资源与配置区，再核对其他内容。

## 测试与交付

单元测试核对版本、范围、包成员、摘要和恢复材料。集成测试使用生产 CLI、传输适配器和内存 Flash，覆盖成功、部分写入、回读或启动失败、恢复重试、候选删除后恢复和 NVS 更新；原生 C++ 目录与布局代码读取真实 E1.45 包，检查害羞接线与进食/平静切换。

另一位 AI 复核实现、测试与本轮记录。现场结果单列 App、资源回读、目录和播放回执；屏幕效果由主人验收。

后续：修复不同尺寸切换的首帧重排 → 害羞播放入口 → 节点播放与替换 → 扩充动画库 → 外壳与客户端角色联动。

## 实现与验证

新入口为 `scripts/deploy-e3f4c-resources.py`。资源计划单独标记 E3f-4c，旧版本入口各自核对 App。95 项事务、CLI、传输和原生目录/布局测试通过；另有 7 项现场记录关联测试通过。

E1.45 包为 5,981,260 B，8 MiB 分区剩余 2,407,348 B。仅增加 `shy_candidate.eaf` 并调整害羞接线，原有素材字节和布局配置保持一致。真实 C++ 代码读取候选后得到 37 项目录，进食仍使用 `full_frame`。

记录：[离线验证](../artifacts/studio-resources-e3f4d/offline-validation.json)与[实现复核](../artifacts/studio-resources-e3f4d/peer-review.json)。
