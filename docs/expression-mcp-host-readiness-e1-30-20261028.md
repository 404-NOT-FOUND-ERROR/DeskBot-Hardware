# E1.30：MCP 主机捕获入口可用性审计

核对日期：2026-10-28。E1.29 已提供配对请求/响应格式、离线转换器和 E1.27 导入工作台。本阶段核对能否在当前电脑端 MCP 主机增加只读捕获入口，以取得真实的 `self.expression.observation` JSON。

## 结论

当前执行环境没有暴露喵伴 MCP 主机或 `self.expression.observation` 工具：本轮可用的 MCP 资源与模板均为空，也没有可调用的外部 MCP 工具。因此无法从这里发起真实工具调用或取得成对的请求/响应。用户口述的最近 24 条语义摘要仍是唯一新增观察信息，不包含原始顺序、时间、准确分布或捕获包。

单独的 DeskBot Online 客户端工作区也不是这次设备工具的捕获点。只读搜索未在 `apps/deskbot-service/src`、其测试和客户端接口合同中发现 `tools/call` 或 `self.expression.observation` 调用链；已有身体桥审计也说明当前服务桥与小智 WebSocket/MCP 协议不是可直接互换的接口。该客户端工作区目前包含大量未提交修改，本阶段没有对它进行写入。

## 本轮边界

- 只读检查可用的 MCP 工具/资源、E1.29 文档和客户端源码入口。
- 未调用设备工具、未访问串口或网络、未改固件、客户端、NVS，也未刷写。
- 未把语音摘要转换成合成的逐条记录；E1.29 的演示 JSON 继续明确标记为合成样本。
- E1.29 的配对格式、校验与导入流程继续有效，不需要改动。

## 后续闸门

需要在当前执行会话中接入**实际发起喵伴 MCP 工具调用的客户端/主机**，或提供该主机工程的本地路径及其请求/响应处理入口。无需提供密钥或聊天内容。确认入口后，下一阶段应在主机收到请求与匹配响应的同一层增加显式开启、被动的捕获钩子：用 JSON-RPC ID 配对，只记录 `self.expression.observation`，保留原始 text block 和电脑接收时间，写入 E1.29 格式；任何非目标工具都不记录，也不改变 MCP 消息。

验收需包括：合成成对请求/响应的单元测试；请求/响应 ID 不匹配、错误返回、重复响应、隐藏字段和超限 payload 的拒绝用例；一次用户发起的真实只读工具调用；导出文件通过 `scripts/export-expression-e1-29.py` 后导入 E1.27；证明未改变工具返回且文件不含聊天文本或会话密钥。取得真实记录后，才进行逐条语义与当前动画映射对照。
