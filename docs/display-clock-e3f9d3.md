# E3f-9d.3：显示传输频率对照

2026-11-13。目标：让主页、菜单及两角色动画完整刷新，消除 E3f-9d.2 启动时的 DMA 供给不足。

## 设计

候选继承 E3f-9d.2 冻结源码，只将板级 `io_config.pclk_hz` 设为 20 MHz。保留 PSRAM 直接发送、4,092 B 分块、队列深度 2、完成回调、菜单与首帧修复。资源、角色和原交互沿用当前版本。

数据流：GFX/LVGL → ST77916 → LCD IO 分块 → PSRAM DMA → 20 MHz QSPI → 屏幕。较低传输速率用于验证 PSRAM 取数和总线竞争；360×360 RGB565 全帧的理论传输时间约 25.9 ms，实机同时观察流畅度。

接口继续使用 `esp_lcd_panel_draw_bitmap` 和现有 App 安装/恢复事务。安装适配器的候选启动检查增加 `DMA TX underflow`、事务回收失败、内存分配失败及刷新错误标记；发现后自动恢复同轮原 App。恢复启动独立检查原版本身份。

依赖：已封存 E3f-9d.2、原 E3f-9d.1 安装参考、当前双角色资源、ESP-IDF 5.5.5 与固定 Python 3.11。刷写前保存当前 NVS，范围仍为 App。
