# 高清分层表情

[打开画质对比](expression-workbench.html?quality=happy) · [English](layered-expressions.en.md)

在工作台选择「高清优化 · 480」。点「画质与完整动作 · 并排看」，左侧选原版或 240 版本，右侧选高清版。可以暂停、拖帧和切换镜像；两版新表情可按表演进度对齐。

## 已完成的优化

| 项目 | 240 交付版 | 高清分层候选 |
| --- | --- | --- |
| 表情画布 | 240×240 放大 | 480×480 原尺寸轮廓 |
| 边缘 | 缩小后的索引色边缘 | 4 bit 灰阶覆盖，编码支持 16 级 |
| 背景 | 每帧存入整图 | 保存颜色，播放时绘制 |
| 进入／收尾 | 每个 EAF 保存整段 | 由眼白、瞳孔、位置与背景计算 |
| 动作主体 | 全脸帧 | 原稿关键帧的局部图层与独立位置 |
| 完整库 | 3,810,366 B（仅 EAF） | 2,083,802 B（AFM + JSON 目录） |

覆盖 29 个语义；idle 与 neutral 共用，28 段完整表演。原版 EAF 为 4,311,337 B。当前高清库比 240 EAF 小约 45.3%，比原版 EAF 小约 51.7%。这是资源文件比较；浏览器的 Base64 包装和运行缓存分别计算。

高清版沿用已认可的动作关键帧、循环闭合、瞳孔先动和左右错拍。它重新读取 480 原生 GIF 的轮廓，在轮廓边缘重建灰阶覆盖；生成稿的背景光晕和噪声继续剔除。它不是从 240 文件放大，也没有把生成稿的纹理全部恢复。

## 对称如何复用

背景、白眼、黑瞳孔和装饰分别管理。每个局部精灵与自己的水平镜像比较，采用统一存储方向；只有尺寸、量化后的覆盖和颜色完全匹配才合并。引用独立记录位置和镜像开关，动作时间属于关键帧。

真正对称的眼形可共用一个精灵；看向一侧时可共用眼形但保留两边的瞳孔位置；单眼眨动、眼形大小差和不同启动时间各自保留。测试素材已验证「反射后共用一份」和「眨眼不被合并」。

本批生成稿含 1,690 个图层引用／1,690 个独立精灵，680 个引用采用镜像存储方向；逐像素匹配后的镜像合并为 0，因此上面的节省来自分层、覆盖压缩和过渡复用。镜像方向不等于合并节省。

## AFM1 解析契约

头部为 ASCII `AFM1`，随后三个 little-endian uint32：版本 1、精灵数、载荷字节数。目录偏移以头部后的载荷起点为基准。`w*h` 不超过 480×480，解码恰好输出指定像素数；偏移、长游程和颜色索引越界均应拒绝。

`a4rle`：一个 token 的高 4 bit 是覆盖 0–15；低 4 bit 加 1 是游程长度 1–16。长度字段为 16 时，读取下一字节，实际长度为 16 加该值，最大 271。覆盖扩展到 alpha 用 `value*17`。

`i8rle`：装饰用 `[count, paletteIndex]` 字节对，count 为 1–255。目录保存该精灵的 RGBA 调色板。

图层引用为 `[sprite, x0, y0, x1, y1, flip]`，矩形右／下边不包含。眼白和瞳孔在各自插值矩形中混合覆盖，再依次合成；背景先绘制，装饰位于眼睛下层。关键帧时间、语义和图层位置独立于存储去重。

下一包先实现按行／分块合成并量测工作缓冲，不直接把旧播放器的全部缓冲扩大四倍。旧 EAF 保留作同图对照。
